`testsets`/`E:\1kt_media` 那 146 个 4×mono 片段上 —— 分组阈值和采样量正是在那批

3. **归档件端到端修复** —— 在真实归档容器上验证"修完残差为 0"。

全程只读 I:, 所有临时文件写在 `E:\1kt_scratch`。

## 1. 留出泛化: 开关开/关完全一致, 但也没有收益

`I:\compact\20260901`（129 个 4×48k×mono、共 31.0 min、时长中位 10.5 s）；
标定语料里没有任何 20260901 片段。

| 分类 | 数量 |
|---|---|
| 逐字段一致 | **516 / 516 轨** |
| 新增修正 | **0** |
| 丢失修正 | **0** |
| 改值 | **0** |
| 文件级 status 变化 | 0 |

### 为什么"零动作"

组结构普查（阈值 1.3）：

| 组结构 | 片段数 |
|---|---|
| `[{CH1} {CH2} {CH3,CH4}]` | **128** |
| `[{CH1} {CH2} {CH3} {CH4}]` | 1 |

**没有任何一个片段是 `[{CH1,CH2} {CH3,CH4}]`（两个都活的麦克风组）** —— 而这是
分组层唯一能够帮上忙的形态。原因是 CH1/CH2 在这批素材上就是**空轨**：
516 条轨里有 **256 条是 `silent_track`**（另外 127 条锚点 / 124 条 `already_aligned`
/ 2 条 `fixed`）。

所以正确的说法是: **在这批素材上, 分组层既不改变任何决策, 也没有提升空间。**
它不是"没用", 是**前提不存在** —— 而"前提不存在时不动作"正是设计要的行为。

同时它给出了 A1/A3 的一个**独立**证据: 在一批没参与标定的真实素材上, 打开开关
的决策与关闭时**逐字段相同**, 而不是靠"我们测过的那批"来担保。

那批素材里仅有的 2 条修正（`C0977` CH4 +3、`C1016` CH4 −4）在两个 arm 里完全
相同，端到端验证 **2/2 逐样本精确**（`max_abs_diff = 0.0`）。

（可用帧 6–8 个，两个 arm 里被修成同一个 1118 采样）。

### 2.2 归档件本身**从未对齐**——而且这是我先前的错，现在纠正了

抽查 4 个归档件，用生产估计器在**归档容器**上直接测量，并与源素材比对：

| 归档件 | 归档件里的偏移 | 源素材里的偏移 | 差值 |
|---|---|---|---|
| `20260904_C1214` CH2 | **+19.6667 ms (944)** | +19.6667 ms | **+0.000** |
| `20260904_C1207` CH2 | **+19.4792 ms (935)** | +19.4792 ms | **+0.000** |
| `20260904_C1178` CH1 | **+20.7500 ms (996)** | +20.7500 ms | **+0.000** |
| `20260904_C1206` CH2 | **+19.5208 ms (937)** | +19.5208 ms | **+0.000** |

两个结论：
- **归档件逐位保留了源素材的偏移** —— 归档过程没有引入也没有消除任何偏移；
- 归档件里**现在仍然带着 19.5~20.8 ms 的声道错位**，因为 `watchfolder.py` /
  `start.bat` 从不转发 `--channel-sync`，这批成品当初就没有做过对齐。

### 2.3 一个必须先说的自我纠正

我先写了一个快速普查脚本（只做 `estimate_pair` + 三个门，不跑复检），它给出
"105 个归档件需要修正"。用生产入口实跑后，正确数字是 **14**。

93 个差异的来源全部查清了，没有一条是模糊的：

| 来源 | 说明 |
|---|---|
| 1 采样的"偏移" | 1 采样 = 0.0208 ms **小于** `aligned_max_ms` (0.05 ms) → 生产判 `already_aligned`。普查用了 `|delay_samples| >= 1` 这个更松的判据，把量化粒度量级的差当成了"要修" |
| `recheck_residual` | `20260830_C0915` CH1 +1191、`20260830_C0922` CH1 +1216：测出、也施加了，**修后复检超过 0.05 ms** → 回退 untouched |
| `non_constant` / `low_confidence` / `silent_track` | 单个固定移位表达不了这些轨 |

**生产入口的数字（14）是有权威性的那个**，普查的 105 作废，两个都写在这里，
不隐藏。

## 3. 归档件端到端修复（真容器, 不重编码视频）

把两个归档件拷到 `E:`，用 alpha 的透明模式重跑：

```bat
python 1kt.py --input E:\1kt_arc\in --output E:\1kt_arc\out ^
  --encoder x265 --preset hq --channel-sync-transparent --jobs 1
```

```
20260904_C1178.MP4 | fixed CH1 (shift 996 samples, 复检残差 +0.0174ms)
20260904_C1214.MP4 | fixed CH2 (shift 944 samples, 复检残差 +0.0017ms)
Transparent finished | done=2 skipped=0 failed=0
```

在**输出容器**上重新测量：

| 文件 | 归档原件 | alpha 重对齐后 |
|---|---|---|
| `20260904_C1214` CH2 | +19.6667 ms = **+944 采样** | **+0.0000 ms = 0 采样** |

残差 **精确为 0**，视频流是 `stream copy`，没有重新编码。
这同时说明: 已经归档的成品**可以原地修复**, 不需要回到源素材重跑。

## 4. 归档里**仍然修不了**的部分，以及为什么

生产拒绝的轨里，仍有 80 条带 **≥1 ms** 的偏移。按原因分组（实测轨迹统计）：

| 原因 | 实例 | 轨迹统计 | 为什么固定移位修不了 |
|---|---|---|---|
| `non_constant` | `20260903_C1171` CH2 +1311 (27.3 ms) | MAD 0.0625 ms, **极差 125 采样 (2.6 ms)**, 漂移 1.46 ms | 单个整数移位只能对一个值; 这条轨在片段内变了 2.6 ms |
| `non_constant` | `20260830_C0914` CH1 +1261 (26.3 ms) | **极差 261 采样 (5.4 ms)** | 同上, 变化更大 |
| `non_constant` | `20260904_C1214` CH1 +1236 (25.8 ms) | MAD 0.25 ms, 极差 110 采样, 漂移仅 0.30 ms | 不是线性漂移, 是**跳变** |
| `low_confidence` | `20260903_C1155` CH1/CH2 ~29–31 ms | 可用帧 **2** 个 | 没有证据, 不该修 |
| `recheck_residual` | `20260830_C0915` CH1 +1191 | 复检 0.05 ms 超门 | 修正被安全网拒 |

**这批 80 条不是分组问题**，是**时变问题**：偏移在片段内变化 2–5 ms，固定延迟模型
在定义上就表达不了。能表达它的是 `--channel-sync-tv`（逐窗时变），而它在本机器的
长素材上实测**不可用**（6 对里只有 1 对达到窗内帧底限 40.8%，其余 <8%）。

所以归档的现状可以一句话概括：

> 14 个文件/轨能被固定延迟修好（其中 13 个当初就没修，1 个是本次分组层新增）；
> 80 条轨的偏移是**时变**的，当前生产路径按设计拒绝，且没有可用的时变路径。
