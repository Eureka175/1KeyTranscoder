## 4. 时变重估：**不是模型问题，是产量问题**

### 4.1 之前的结论与它的前提

P3/P4 记的是"两个长片上 6 对里只有 1 对达到窗内帧底限（40.8 %），其余 <8%，长素材上不可用"，
根因记为"跨组不相关"。但那 6 对里有一半是**跨组对**（CH1/CH2 对 CH3/CH4），本来就不该相关。
分组锚点做出来之后，跨组对应被排除 —— 所以先重跑**组内对**。

### 4.2 组内对依然达不到窗底限（生产几何 30 s 窗 / 10 s 跳 / 每窗 ≥3 帧）

| 组内对 | 时长 | 达到窗底限 | 覆盖率 |
|---|---|---|---|
| `C1305` CH1→CH2 | 80.1 min | 21 / 478 | **4.4 %** |
| `C1305` CH3→CH4 | 80.1 min | 0 / 478 | **0.0 %** |
| `C1306` CH1→CH2 | 69.4 min | 17 / 414 | **4.1 %** |
| `C1306` CH3→CH4 | 69.4 min | 0 / 414 | **0.0 %** |

**结论 1：之前"不可用"的判定不是锚点选错造成的。** 换成组内对，覆盖率依旧 4 %。

### 4.3 而且在测到的窗里，偏移基本是恒定的

| 组内对 | 固定延迟残差 | 逐窗残差 |
|---|---|---|
| `C1305` CH1→CH2 | max 0.10 ms / rms 1.7 采样 | rms **0.7** 采样 |
| `C1306` CH1→CH2 | max 0.08 ms / rms 1.2 采样 | rms **0.8** 采样 |

**结论 2：逐窗修正能把残差从 1.7 降到 0.7 采样，即 0.035 ms → 0.015 ms。** 这是
`verify_max_ms = 0.05 ms` 量级以下的变化，收益没有材料性。长片的问题不是"偏移在变"，是"大部分窗没测到"。

### 4.4 归档里被判 `non_constant` 的轨：0 个窗达标

取 `non_constant` 且 ≥1 ms、时长 ≥60 s 的 14 条轨（127–170 s）：**全部 `0 / N` 达标**
（N = 7~14 个 30 s 窗）。同样不是时变的用武之地。

### 4.5 那它们为什么被判 `non_constant`？—— 稀疏 + 单个离群帧

`20260830_C0914` CH1（127.1 s）逐步拆开：

| 量 | 值 |
|---|---|
| 总帧 / 可用帧 | 1270 / **48 (3.8 %)** |
| 可用帧在时间轴上的分布（分 10 段） | `[0,0,0,4,5,3,7,4,10,15]` —— **前 30 % 一帧都没有** |
| 帧值 | 几乎全是 +1254…+1267，**其中 1 帧是 +1012** |
| 原始极差 | **261 采样 = 5.44 ms**（> 1.0 ms 门）→ 判 non_constant |
| 去掉那一帧后 | 全部落在 **13 采样 = 0.27 ms** 内 |

`classify_constant` 的第三道门**故意**用原始 min–max（注释写明是为了拦"中间真的跳了"），
它对**单个离群帧**同样敏感。两者该区别对待：真跳变两侧都有很多帧，单帧离群则固定延迟完全够用。

### 4.6 但"改成抗离群"只救回 2 条

对全部 57 条 `non_constant` 且 ≥1 ms 的轨，分别用当前门与"p1–p99 修边"门判定：

| 项 | 数量 |
|---|---|
| 被查轨 | 57 |
| 当前门判非恒定 | 48 |
| **改 p1–p99 后翻转为恒定** | **2**（`C1176` CH2、`C1203` CH2） |
| 翻转者里"只有 1 帧在门外" | 2 / 2 |
| 翻转后最大 MAD / 最大 p1–p99 | 0.0417 ms / 0.682 ms |

**结论 3：离群鲁棒性是真问题，但杠杆只有 2/57。** 值得记一笔，不足以解释 80 条。

### 4.7 真正的瓶颈：合格帧**密度**

按判定分组的合格帧产量（占该片段总帧数）：

| 判定 | n | 中位产量 | p25 | p75 |
|---|---|---|---|---|
| `already_aligned` | 289 | **73.3 %** | 56.6 % | 86.3 % |
| `fixed` | 14 | **25.1 %** | 14.7 % | 26.1 % |
| `non_constant` | 63 | **10.0 %** | 5.3 % | 23.3 % |
| `low_confidence` | 19 | **1.7 %** | 1.2 % | 2.2 % |

绝对合格帧数却几乎一样：`fixed` 中位 48.5 帧 vs `non_constant` 中位 51.0 帧。

**结论 4：区分"能修"与"被拒"的不是帧数，是**密度**（同样多的可用帧散布在更长的片段上）。
所以要让这 80 条轨可修，杠杆是**提高逐帧测量的合格产量**（`peak >= 2 x noise_floor` 那个
每帧判据 / 估计器灵敏度），**不是换延迟模型**。**

## 5.1 透明模式的元数据保全（v0.8.7 修复）

透明重封装原本只把轨道搬过去，容器层全部丢失。接上 `--check` 后立刻暴露，
修复前后（`20260904_C1214`，`--check full`）：

| 项 | 修复前 | 修复后 |
|---|---|---|
| `ftyp` | `isom` | **`XAVC`** |
| `rtmd` 的 `tref/cdsc` 关联 | 丢失 | 保留 |
| `nrtm` 镜头档案 | 整项缺失 | 保留 |
| `uuid` PROF / UNKNOWN / USMT | 0 / 0 / 2 | **1 / 1 / 7**（补插 7 个） |
| Gyroflow 消费端 | **FAIL**：IMU 0/146146，认不出相机 | **PASS**：IMU 146146，`Sony ILCE-7M5`，标识与时间线均匹配 |
| 详细自检（68 项） | 54 PASS / **13 FAIL** | **68 PASS / 0 FAIL** |
| `validate.compare` | 34 PRESERVED / 2 MODIFIED / 4 MISSING | **45 / 0 / 0** |

做法是把 `preservation/pipeline.py` 的第 4~5c 步原样复用到透明重封装上：
`mux_new(stage)` → `sony.reconstruct`（tref/cdsc + nrtm）→ `gpac.flatten`
→ `gpac.set_brand` → `isobmf.insert_uuid_boxes(stage→dst)` → nrtm `item_type` 补丁。
流层面同时保持：源轨顺序、video/rtmd/三条音频 packet md5 相同、被修正轨 CH2 残差 0。

`--check` 三级在透明模式下与正式编码严格同一套语义；唯一差别是 `full` 里的
PSNR/SSIM —— 视频是 stream copy，两侧编码帧逐位相同，该子项单列为
`SKIPPED_NOT_APPLICABLE` 并打 INFO，其余 full 项（详细自检/深度项）照常执行。
