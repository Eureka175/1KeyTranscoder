## 1. Tracked code, and where it lives

```text
tests/audio_sync_acquisition/generate_signal.py
tests/audio_sync_acquisition/make_operator_package.py
tests/audio_sync_acquisition/preflight.py
tests/audio_sync_acquisition/ingest.py

tests/audio_sync_acquisition/acquire_common.py
tests/audio_sync_acquisition/schema.json
tests/audio_sync_acquisition/README.md
```

**Why not `tools/`.** `.gitignore` line 32 ignores `tools/` wholesale — it holds the
vendored `ffmpeg.exe`, `ffprobe.exe` and the GPAC/NVEncC/QSVEncC distributions, and
`git ls-files tools` returns **nothing**. Tracked acquisition code cannot live there
without `git add -f`, and doing so would contradict the release manifest's tool
whitelist, which expects `tools/ffmpeg.exe` and `tools/ffprobe.exe` and nothing
else. `tests/` is the repository's tracked home for tooling of this kind
(`tests/selftest/`, `tests/hwdecode/`).

This is worth recording because the P4.11 brief suggested `tools/audio_sync_acquisition/`
as an example path. Following it literally would have required forcing tracked files
into an ignored directory.

## 3. Reproduction

```powershell
# the signal and the operator package
python tests/audio_sync_acquisition/generate_signal.py
python tests/audio_sync_acquisition/generate_signal.py --verify
python tests/audio_sync_acquisition/make_operator_package.py

# the fixtures, then the end-to-end test
python work/p4.11-acquisition/make_fixtures.py
python tests/audio_sync_acquisition/test_e2e.py

# preflight and ingest on the fixtures (or on a real delivery)
python tests/audio_sync_acquisition/preflight.py --input work/p4.11-acquisition/fixtures
python tests/audio_sync_acquisition/ingest.py --takes work/p4.11-acquisition/fixtures

# the protocol audit measurements
python work/p4.11-acquisition/verify_signs.py
python work/p4.11-acquisition/sign_chain.py
python work/p4.11-acquisition/marker_design.py
```

`make_fixtures.py` builds 25 takes by muxing deterministic PCM into MP4 containers
with a synthetic video track. It is a `work/` script, not tracked tooling: it exists
to test the tracked tools, and the fixtures it writes are 1.4 GB of media that must
not enter version control.

```text
harness defects found and fixed : 8, and each produced a confident wrong answer
  first (see §15 of the tooling document and the commit messages)
production defects found        : 0
production files changed        : 0
thresholds lowered              : 0
```

The eight, in the order they were found:

1. the marker duration conflict was measured against the wrong quantity (absolute
   localisation against unrelated noise) before the differential measurement was
   identified as the one that matters;
2. `localise()` reported `-m` instead of `m`, producing a clean, confident −2000 for
   a marker at +2000;
3. the fixture's `mapping or default` replaced a deliberately ambiguous mapping with
   a valid one, so the negative control passed;
4. the ambiguous-mapping check rejected any value **containing** a channel token,
   which would have failed every correctly filled note;
5. the format check compared the take's codec against the manifest's WAV format, and
   `pcm_s16be` carries no `bits_per_raw_sample`, so neither the codec check nor the
   bit-depth check caught it;
6. `MARKER_CORRUPT` keyed off the differential peak-to-sidelobe ratio, which stays at
   ~30 dB whether or not the marker is present;
7. that presence test compared at zero offset only, so every correctly **shifted**
   take reported its marker absent;
8. refusals were not persisted, so re-runs re-decoded takes already known to be
   ineligible, and the constant-delay eligibility guard did not exist at all — both
   time-varying fixtures were reported as plain `CORRECTED`.
