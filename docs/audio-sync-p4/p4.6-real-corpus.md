## 2. 两组判据，不是同一个检查

### 判据 A —— 逐字节复现 P3.11 冻结的修正 PCM

P3.11 为它产出的每一条修正流记录了 `dst_sha256`（由**另一套代码**生成）。若本阶段
的实现能从同一源、同一冻结移位序列复现那些字节，则**施加机制与坐标合同和研究生
成链完全一致，逐位一致**。这是对 **correction mechanics** 最强的可用判据。

期望值从磁盘上的 `*_apply_meta.json` 读取，不手工转录。

### 判据 B —— 独立复测残差

用本 harness 自带的互相关估计器（numpy FFT 互相关 + 抛物线细化，
**不用** `core.sync_estimate.gcc_phat_int`），逐探针测量修正输出与参考声道之间的
延迟。这度量的是 **estimator quality**，与判据 A 是**不同的问题**：正确施加了移位
不代表估计准确；残差下降不代表所有窗都可信。

**不施加任何 residual acceptance 门槛**：D3 是 `NOT ESTABLISHED`，这些数字是观测量，
不是合格判定。

## 4. 为什么残差要分两个总体报告

第一次实现把探针从**已测量窗列表**里取（每 `len(valid)//24` 个取一个），于是所有探针
都挤在前一段已测窗里，**从未探到缺口**——统计量描述了一个并非真实流的总体。

现在探针在**时间上均匀分布**，并且每个探针**记录它落在哪个窗、那个窗是什么状态**：

| 总体 | 含义 |
| --- | --- |
| **全部探针** | 包含跨缺口/未决窗的探针 |
| **仅已测窗内** | 探针的整个跨度落在一个 `TRUSTED`/`REENTRY` 窗内 |

一个跨窗边界或落在未决窗内的探针，其输出由**缺口策略**决定。把它的残差读成估计误差，
就是把一个**有意的策略取值**归因成测量错误。两个总体都报告，**一个都不丢**。

实测对比（绝对值中位数，samples）：

| pair | 全部(before) | 全部(after) | 仅已测窗(before) | 仅已测窗(after) |
| --- | --- | --- | --- | --- |
| C1305 ch3→ch1 | 1144.0 | 31.941 | 1148.0 | **8.000** |
| C1305 ch3→ch2 | 1152.0 | 236.000 | 1152.0 | **8.000** |
| C1305 ch3→ch4 | 352.9 | 2.973 | 409.1 | **2.952** |
| C1306 ch3→ch1 | 1248.0 | 78.471 | 1128.0 | **16.000** |
| C1306 ch3→ch2 | 1256.0 | 16.000 | 1256.0 | **16.000** |
| C1306 ch3→ch4 | 136.8 | 3.448 | 174.5 | **1.719** |

**结论（分开陈述，不合并）**

* **correction mechanics：通过。** 判据 A 六对全部逐字节一致；独立复测在已测窗内
  的残差降到个位数样本（中位数 1.7–16.0 samples，p95 全部 ≤ 16）。
* **estimator quality：测量层本身有大量缺口。** 覆盖率从 0.19 到 0.74 不等，最好
  的一对也只有 73.9 %。全部探针的 p95 仍然较大（最高 821 samples），因为这些探针
  落在缺口上，其输出由 `hold` 策略填充。
* 因此："残差下降了" **不等于** "所有窗都可信"；"正确执行了 shift" **不等于**
  "估计准确"。这两句话在本阶段是被数据分别支持的，不是口号。

### 判据 A 自身的一个缺陷（在它能误导之前被修好）

`load_frozen_meta()` 最初按**路径**给记录建键（用 `p.parent.name` 当 stem）。父目录
其实是**坐标**（`latest-start` / `nearest-centre`），而 `explicit_state` /
`no_correction_gap` 含下划线，于是 36 条记录里有 18 条被打上
`('latest-start', ...)`，判据 A **一条都找不到**，报告 `frozen_p311_match: None`
——读起来像"不适用"，而不是"坏了"。现在按记录**自身**的
`stem`/`pair`/`policy`/`coordinate` 字段建键。

**一个开不了火的判据比没有判据更糟**，因为它看起来像通过。

## 6. 生产入口的端到端验证（合成已知延迟素材）

**真实 C1305/C1306 素材无法到达逐轨时变步骤**，原因在测量层而不在 P4.6：

```text
C1305 ch3→ch1 : 可用帧 6/5999 (0%)   -> evidence_insufficient
C1305 ch3→ch2 : 可用帧 5/5999 (0%)   -> evidence_insufficient
C1305 ch3→ch4 : 可用帧 13/5999 (0%)  -> evidence_insufficient
-> measure_failed，在到达逐轨修正之前短路
```

覆盖率门是 60 %（`min_usable_fraction`），10 分钟片段上 C1305 最好的一对也只有
51.4 %（全片 40 分钟）。这是 P4.2 有意收紧的**生产证据语义**，本阶段**没有放宽它**，
也没有为让它通过而更换 fixture。

因此 opt-in 的**执行**分支用一份**声明为合成**的素材单独验证：4 条单声道 PCM、
48 kHz、4 分钟、已知延迟（CH1 +1500、CH2 −900、CH4 +2400 samples，CH3 为锚）。

### 三个配置下的实测行为

| 配置 | 结果 |
| --- | --- |
| 默认（无 `time_varying`） | `applied`，3/4 轨 fixed；**没有任何报告行带 `time_varying` 块** |
| `time_varying=True`，无 policy/coordinate | **`tv_not_configured`**，拒绝并给出完整原因；**不静默退回固定延迟** |
| `time_varying=True` + `hold` + `latest-start` | `applied`；**3 条轨的时变路径全部执行**，每轨 24 窗，全部 `TRUSTED` |

执行详情（每条轨）：

```text
n_frames=2399  n_finite_frames=2399  n_frames_outside_plan=0
min_frames_per_window=3  n_windows=24  n_windows_meeting_frame_floor=24
verification.ok=True  checked_samples=11,520,000 / 11,520,000
```

### 独立复核（15/15 通过）

| 检查 | 结果 |
| --- | --- |
| BEFORE CH1 / CH2 / CH4 与声明延迟一致 | +1500.00 / −900.00 / +2400.00，误差 **0.00** |
| AFTER 输出样本数 == 输入 | 11 520 000（4 条轨全部） |
| AFTER 与锚的残差（独立估计器） | 中位数 **+0.000**，最差 **0.000** samples |
| AFTER 内部区与锚的差异 | rms_err/ref = **0.00000000**，**逐位相同** |

修正输出在 11 131 200 个内部样本上与锚**逐位相同**。边界 `guard` 样本被排除，因为
`out[k] = in[k + S]` 在流两端会越界补零（不变量 I7）而锚在那里有真实内容——那是
**契约规定的补零**，不是缺陷。

### 复核器自身的一个精度缺陷

第一版 `independent_delay` 的粗扫步长是 8，于是粗峰被量化到 8 的倍数：声明 −900 的
fixture 被报成 **−904**，而这个"独立"判据比它所要审计的生产估计器（测得 −900.000）
**更不准**。步长已改为 1。

**判据不该是房间里最不准的仪器。**

## 7. 视频 / 封装兼容性

本阶段专注音频。两条如实陈述：

1. 上面那份 4 分钟 fixture **没有视频流**（4 条单声道 PCM），因此它**不能**验证
   "视频 stream copy 保持完好"。
2. 早先尝试用 `--channel-sync-transparent` 跑 P4.4 的 2.3 MB clip 被
   **`probe failed (No video stream found.)`** 跳过——同样因为没有视频流，而不是
   因为时变路径有问题。

时变路径写的是**与固定路径同一个**逐轨 raw 文件（`fixed_raw[i]`），而第 7 步的重编码
与重封装对它一视同仁；因此对封装的影响面等同于已发布的固定延迟路径。这个论断是
**结构性推理**，不是一次视频回归的实测结果——**未做视频回归**。
