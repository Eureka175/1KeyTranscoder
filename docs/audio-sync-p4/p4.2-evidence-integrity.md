## 1. The bug

`core/channel_sync.py` evaluated an evidence gate against a **candidate**
estimate, then adopted a **different** estimate that had never passed it, and
wrote the result as a successful fix.

```python
# before P4.2, the coverage branch
elif coverage < eff["min_usable_fraction"]:          # gate fires
    ew = wide_estimate(i)                            # different candidate
    if (ew.usable_frames >= eff["min_usable_frames"]
            and ew.confidence >= eff["min_confidence"]):
        e, stats = ew, ...                            # ADOPTED
        used_est[i] = ew
    ...
# and later, the final decision re-checked confidence / constancy / range --
# but NEVER coverage
rows[i] = est_row(i, e, stats, "fixed", None)        # -> SyncStatus.SUCCESS
```

Three things were wrong together:

1. **the adopted wide estimate was never re-checked for coverage** — the gate
   that fired on the narrow candidate was not applied to its replacement;
2. **the final decision did not check coverage at all**, so `SUCCESS` rested on a
   local variable (`e`) whose evidence had already left scope;
3. **the evidence that justified the decision was not published** — `est_row`
   carried `usable_frames` but no `total_frames` and no fraction, so no consumer
   could recover how much of the track was actually measured.

The failure mode is the one `PRODUCTION-REQUIREMENTS.md` U1 names:

> **The failure mode this requirement exists to eliminate:**
> `number exists == measurement exists`.

The threshold is `ceil(min_usable_fraction × total_frames)` computed from

`min_usable_fraction` or the frame geometry moves the expectation with it and the
suite fails loudly rather than silently ceasing to test anything.

## 3. Root cause

Two independent gates existed and only one of them was applied to the object that
mattered.

```text
candidate estimate A  ->  gate(A)  ->  reject
adopted estimate   B  ->  (no gate) ->  ACCEPT  ->  SUCCESS
```

The condition is not a missing check in the abstract — it is a **check applied to
the wrong object**. `coverage` was computed from `e` before `e` was replaced by
`ew`; after the assignment the value was stale, and nothing recomputed it.

## 4. The corrected gate

One predicate, applied to whichever estimate is chosen.

```python
def evidence_ok(ev) -> tuple[bool, str | None]:
    if ev["usable_frames"] < eff["min_usable_frames"]:
        return False, "low_confidence"
    if not (ev["confidence"] >= eff["min_confidence"]):
        return False, "low_confidence"
    if ev["coverage"] < eff["min_usable_fraction"]:
        return False, "evidence_insufficient"
    return True, None
```

Applied at **three** points, which is what makes the family closed rather than
the instance patched:

| point | what it prevents |
|---|---|
| `try_wide()` — before adopting a wide re-measurement | adopting a replacement that never passed the gate |
| the narrow "no usable frames" branch | the same, for the estimator-failed path |
| the **final adoption gate**, on the chosen estimate | any future path that reaches `fixed` with evidence that has gone stale |

`try_wide` returns a **third** value — the reason it did not pass — so the caller
cannot adopt an estimate that failed, even by accident.

### 4.1 The reason code

`evidence_insufficient`, mapped in `_SYNC_REASON_STATUS` to
**`SyncStatus.LOW_CONFIDENCE`**.

That is deliberate. The brief's §2 and §12 require distinguishing *"there is a
value but the evidence is insufficient"* from *"the estimator failed"*. The
existing enum already expresses the first — `LOW_CONFIDENCE` is exactly "a number
exists and is not trusted" — so **no new status was minted**, and the new code
exists only to distinguish *which* gate rejected: a correlation peak that never
cleared the threshold, versus evidence broken up by gaps. It is also added to
`_ESTIMATION_FAIL_REASONS`, so the file-level verdict treats it like the other
estimation failures.

The three semantics remain distinct:

```text
fully evidenced success        -> decision="fixed",          SyncStatus.SUCCESS
value exists, evidence thin    -> decision="untouched",      reason="evidence_insufficient"
                                  -> SyncStatus.LOW_CONFIDENCE
no measurement at all          -> decision="untouched",      reason="insufficient_frames"
                                  / "no_valid_anchor" / "non_constant" / ...
```

## 5. State semantics

```text
offset_samples   is the EXECUTION dimension   - what to apply
evidence         is the EPISTEMIC dimension   - why it may be believed
```

`offset = 615` with `usable_frames = 5` is a **valid numeric observation** and
must not be silently promoted to a **trusted production sync result**. P4.2
enforces that at the point where the promotion happened.

## 6. Evidence fields

Every decision row now carries:

```python
rows[i]["evidence"] = {
    "usable_frames": int,     # frames whose measurement was accepted
    "total_frames":  int,     # frames in the track's trajectory
    "coverage":      float,   # usable / total, in [0, 1]
    "confidence":    float,   # the estimate's own confidence
}
```

The brief's §7 requires that a final result be able to **explain why it was
accepted**. `total_frames` and `coverage` were previously computed and thrown
away one line later; `min_usable_fraction` and `min_usable_frames` are readable
from `DEFAULTS`. A consumer holding the row can now reconstruct the decision.

**Scope, stated:** P4.2 attaches evidence to the **report row** — the producer's
object. It does **not** extend `AudioSyncResult`. That is D1's design and remains
a separate, outstanding change (`work/p4.1/D6-RESULT.md`, test `T5.4`).

### The core question, answered

> **After the fix, can a path still exist where evidence is insufficient but the
> result is reported as SUCCESS / `fixed`?**

**No**, on three independent lines of evidence:

1. **source audit** — the gate is applied at every adoption point, and a final
   gate re-checks the chosen estimate; the static audit found no second instance
   of the family in 51 modules;
2. **deterministic regression** — 35 cases across the whole evidence spectrum,
   including `ADOPT-BAD` (candidate A sufficient, B insufficient, B chosen) and
   an invariant over six regimes asserting that **no `fixed` row anywhere carries
   coverage below the gate**;
3. **real corpus** — five of six real pairs that would have been published as
   successful fixes are now classified `LOW_CONFIDENCE`, while the one pair whose
   evidence genuinely suffices (74.4 %) still succeeds.

**This is a legal and expected endpoint.** What it is *not* is an all-green line:
one frozen P1 record is now correctly non-success, one D6 XFAIL remains open
against D1, and one test suite is blocked by machine memory rather than by code.
All three are recorded above rather than smoothed over.
