## 1. What was reused rather than rewritten

P4.10 adds **no** estimator, **no** ffprobe parser, **no** plan, **no** correction
and **no** media processing. Every fact about the material comes from production
code:

| need | production source | how |
|---|---|---|
| container / stream facts | `core.probe.probe_streams` | the same `-show_entries` field table as the production video probe |
| audio model view | `core.audio_probe.build_audio_streams` | the same builder the production path uses |
| PCM decode | the same `ffmpeg -map 0:a:N -f f32le -ac 1 -ar 48000` invocation as `channel_sync._decode_stream` | bounded windows, deleted after use |
| measurement | `core.sync_estimate.estimate_pair` | called directly at the production geometry |
| evidence gate | `core.channel_sync.effective_opts(None)` | thresholds **read**, never typed in |
| independent verifier | carried in `work/p4.10-source/verifier.py` | see §3 |

## 3. Cross-phase dependency, stated rather than assumed

P4.9B's independent verifier lives under `work/p4.9b/`. Importing it from P4.10
would make this phase silently depend on another phase's working tree — files that
phase owns and may move. The verifier is therefore **carried into**
`work/p4.10-source/verifier.py`, and its provenance is documented there:

* it is P4.9B's **corrected** implementation, including the lag-axis fix that
  P4.9B found (`c[m]` for `m >= 0`, `c[nfft + m]` for `m < 0`, where `nfft` is the
  **padded** length);
* the fix's rationale, the defect it repairs and the measurement that exposed it
  are recorded in `docs/audio-sync-p4/p4.9b-residual-calibration.md` §1.1;
* P4.10 re-verified nothing about it and claims nothing new about it.

## 4. Reproduction

```powershell
# 1. inventory every media container (metadata + a bounded per-channel probe)
python work/p4.10-source/inventory.py

# 2. truth-anchor audit and truth grading
python work/p4.10-source/classify.py

# 3. what the production corpus's four streams actually ARE
python work/p4.10-source/channel_forensics.py

# 4. cross-method agreement on real stereo material
python work/p4.10-source/stereo_consistency.py

# 5. the tracked documents, generated from the artifacts
python work/p4.10-source/assemble.py
```

The template for the tracked document is `work/p4.10-source/doc-template.md`, read
on every run. Filling the output in place would destroy its placeholders and make a
second run produce empty sections — the same input-is-not-an-output fault that
P4.9A and P4.9B each recorded.
