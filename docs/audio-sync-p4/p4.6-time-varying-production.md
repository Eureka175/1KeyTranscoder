## 1. 这一阶段做了什么

`core/audio_sync_tv.py` 早就能规划逐窗修正并施加它，但没有任何生产模块导入它，
因为两个产品决策未决（D2 gap policy、D5 coordinate contract）。P4.6 不解这两个
决策，而是把"未决"变成**显式、可拒绝的调用契约**：

> 调用方必须自己说出用哪个 gap policy、哪个 coordinate contract；说不出来就
> **拒绝执行**，而不是替它选一个实现默认值。

这条规则让能力可以安全交付：能力可用，产品语义仍未被擅自决定。

## 2. 生产入口

### 模块

`core/audio_sync_tv_exec.py` —— **唯一**的生产边界。它是 `core/` 中除
`audio_sync_tv.py` 自身外**唯一**导入该模块的文件（`channel_sync.py` 也导入，
但从**函数作用域**导入；见 §7）。

### 调用面

```python
from core import audio_sync_tv_exec as tve

request = tve.request_time_varying(          # 缺 policy/coordinate -> 立即拒绝
    enabled=True,
    policy="hold",                # D2 —— 必须显式指定
    coordinate="latest-start",    # D5 —— 必须显式指定
    window_samples=1_440_000,     # 缺省 = P3 冻结的生产几何 (30 s)
    hop_samples=480_000,          # 缺省 = 10 s
)
plan = tve.build_time_varying_plan(src, request=request, measurements=records)
result = tve.execute_time_varying(src, dst, plan=plan)   # 原子写入 + 独立复测
```

一次性入口：`tve.run_time_varying(src, dst, request=..., measurements=...)`。
**任何拒绝都以 `TimeVaryingSyncResult(executed=False, reason=<稳定码>)` 返回，
原音频与 `dst` 都不被触碰。**

### 生产分流

`core/channel_sync.run_channel_sync()` 的逐轨修正步骤按 `opts` 分流：

```python
if eff["time_varying"]:
    ..._apply_time_varying_track(i, e, arrs[i], fixed_raw[i], ...)
else:
    sync_fix.shift_stream(...)          # P1 原路径，逐字节不变
```

`arrs[i]` / `fixed_raw[i]` 是**既有**的解码产物与既有输出文件——时变路径写的是
同一个文件，因此第 6/7 步（复检、重编码、重封装）不需要任何重构。

### CLI

```text
--channel-sync-tv                                  显式 opt-in（默认关闭）
--channel-sync-tv-policy {hold,no_correction_gap,explicit_state,linear,next}
--channel-sync-tv-coordinate {latest-start,nearest-centre}
```

`--channel-sync-tv` 隐含 `--channel-sync`。**`current` 不在可选列表内**。

## 3. 执行路径

```text
测量（已存在，本阶段不重做）
    PairEstimate.frames: 200 ms 帧 / 100 ms 跳, NaN = 该帧不可测
        ↓
适配（P4.6 新增）
    aggregate_frames_to_windows: 帧 -> 计划窗（30 s / 10 s）
        ↓
计划
    build_correction_plan: mask 由声明有效性派生, 绝不接受外部 mask
        ↓
坐标 + 缺口策略（**调用方显式指定**）
        ↓
资格 / 状态传播

        ↓
分块 PCM 施加
    apply_shift_plan: out[k] = in[k + S[join(k)]], 越界补零, n_out == n_in
        ↓
独立复测
    verify_applied_shift: 逐样本, join 由**独立实现**重新推导
```

## 4. Evidence / State 契约

`window_evidence(plan) -> EvidenceContract`：逐窗证据分布，**不是**一个 SUCCESS。

| 字段 | 含义 |
| --- | --- |
| `n_windows` / `n_measured` / `n_unresolved` | 窗数 / 有被接受测量的窗 / 未决窗 |
| `coverage_fraction` | `n_measured / n_windows` |
| `state_counts` | 全部窗的状态计数 |
| `measured_state_counts` | **只算有测量支撑的窗**——与上者分开，使簿记提升可见 |
| `gate` / `coverage_gate_ok` | 生产**实际生效**的门（来自 `channel_sync.effective_opts`，不写字面量）；`None` = 无法判定，不是"不满足" |
| `n_overclaimed` | 声称了没有的测量的窗数（生产恒为 0） |

状态：`TRUSTED` / `UNRESOLVED_GAP` / `REENTRY`，定义为 `resolved` mask 的纯函数。
`UNRESOLVED_GAP` 是**合法认知状态，不是错误**。

每个 sample 最终使用哪个窗：`plan.shift_at(pos)` / `plan.window_of(pos)`，按 plan
声明的坐标合同求值。`TimeVaryingSyncResult.refusals` 给出状态→窗数聚合，因此"这段
音频为什么没被校正"不需要调试器。

## 5. Gap Policy 支持（D2 仍 DEFERRED）

`PRODUCTION_POLICIES = ("hold", "no_correction_gap", "explicit_state", "linear", "next")`

| 策略 | 缺口内的实际 sample 行为 | 在线 | 证据要求 |
| --- | --- | --- | --- |
| `hold` | 前向携带最后一个可信移位；前导缺口为 0 | 是 | 无额外 |
| `no_correction_gap` | 缺口内一律 0（完全不需要上下文） | 是 | 无额外 |
| `explicit_state` | 与 `hold` 逐位相同的移位；状态为一等输出 | 是 | 无额外 |
| `linear` | 缺口两侧线性插值 | **否（离线）** | 必须显式给 `GapContext.gap_endpoints` |
| `next` | 缺口内用下一个可信移位；尾部缺口为 0 | **否（离线）** | 无额外 |
| `current` | —— | —— | **不在生产白名单**，请求即拒绝 |

保证：

1. 每个策略对 sample 的实际行为在 §5 表里写明，并由测试断言（T15/T49）；
2. 缺口区间仍保留 `UNRESOLVED_GAP`，**不因策略而改变**；
3. 无测量证据的窗不会被标成实测可信——`mask_is_authoritative` 与
   `overclaimed_windows() == 0` 双重保证，违反即拒绝执行；
4. 状态不随 chunk 边界改变（T36：256/1024/4096/16384/480000 五种块大小，
   输出 **sample-identical**）；
5. 缺口内的数值从不伪装成 measured truth：`CorrectionDecision` 在**类型层面**
   要求 `UNRESOLVED_GAP` 只能由 `source="policy"` 构造。

### 一个已知的实现缺陷（本阶段记录，未修改）

`_fill_linear` 校验 `gap_endpoints` **在场**却在缺口内**从不使用**它：前导缺口用
一个本身未决的窗的值插值到自己（`i == 0`），尾部缺口同理。`linear` 是离线专用、
不参与任何生产声明，但它**与文档不符**。已由测试固定实际行为，未被"顺手修好"，
因为修改它会改变 `core/audio_sync_tv.py` 的既有语义，而那不在本阶段授权范围内。

## 6. Coordinate Contract（D5 仍 DEFERRED）

`COORDINATES = ("latest-start", "nearest-centre", "sample-domain")`
生产入口只接受前两者；`sample-domain` **与 `latest-start` 是同一个函数**，保留它
只为让"第三个候选"这个误用**可被明确拒绝**（`window_sample_domain` 在
`window < hop` 时报错）。

生产入口**没有默认坐标**：缺 `coordinate` 即
`Refused(audio_sync_tv_coordinate_required)`。

实测关系（T18，生产比值 `win = 3*hop`）：

```text
off = hop//2 - win//2 = 240000 - 720000 = -480000 = -hop
```

即 nearest-centre 的 join **整窗落后**一个窗（不是半个）。因此两者读到的 source
索引在 2 400 000 个样本中的 **1 920 000** 个不同（由两条 join 与 plan 的移位
序列**派生**，不是猜的）。注意**值**的差异（1 320 000）**小于**索引差异，因为测试
信号是周期性的——两个不同的索引可以携带相同的 float。这两个数字不可互换。

## 7. PCM 施加

契约：`out[k] = in[k + S[join(k)]]`，越界读补零，`n_out == n_in`。

* 逐块按**相同窗**切段，每段一次 `stream.read_into`，**没有逐样本 Python 循环**；
* 段边界用**精确闭式** `(w+1)*hop - off`，不是"至少前进一个样本"
  （后者在坐标滞后时退化成单样本循环，实测把一次 2 s 的 apply 变成分钟级）；
* 不物化每样本坐标标签（P3.11 自己的实现物化 int64/样本 = C1305 长度上 1.8 GB，
  峰值 RSS 3632 MiB；本实现 173 MiB 平）；
* **原子写入**：先写 `dst` 同目录的 `.part`，验证通过后才 `os.replace`。施加或
  验证失败时删除 `.part`，`dst` 不被创建/覆盖。

不伪造同步：不重复帧、不重复末样本、不静音填充、不静音截断、不编造延迟。路径无法
安全执行时返回明确状态或错误。

## 8. 拒绝码

| 情形 | 码 |
| --- | --- |
| 未指定 policy | `audio_sync_tv_policy_required` |
| 未指定 coordinate | `audio_sync_tv_coordinate_required` |
| policy 不在生产白名单（如 `current`） | `audio_sync_tv_policy_not_production` |
| plan 不合法 / 未知策略或坐标 / 帧数门为 0 | `audio_sync_tv_plan_invalid` |
| 完全没有测量记录 | `audio_sync_tv_evidence_insufficient` |
| 一个可信窗都没有 | `audio_sync_tv_no_trusted_window` |
| 缺口未决（结构性事实） | `audio_sync_tv_gap_unresolved` |
| 施加失败 | `audio_sync_tv_apply_failed` |
| 独立复测不通过 | `audio_sync_tv_verification_failed` |

## 11. 已知限制

1. **`channel_sync` 的时变逐轨路径在真实 C1305/C1306 上不可达**：测量证据门
   （60 % 覆盖率）先拒（C1305 最佳轨 51.4 %，10 分钟片段 5–13/5999 帧），于是
   `measure_failed` 在到达逐轨修正步骤之前就短路。这是**测量层的既有生产语义**，
   不是 P4.6 的缺陷，本阶段未放宽它。
2. **D2 未选定**：没有全局默认策略；调用方必须指定。
3. **D5 未选定**：没有全局默认坐标；调用方必须指定。
4. **D3 未建立**：不引入任何 ±N 样本的 residual acceptance 门槛；
   `ResidualSummary` 连 `passed` 字段都没有。
5. `linear` 策略的端点处理与文档不符（§5）。
6. A7M5 原始素材不在本机；其**测量结果**以冻结 fixture 形式存在。
