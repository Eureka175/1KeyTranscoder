## 2 测试矩阵

### 2.1 设计原则

1. **每一层必须说明它能证明什么、不能证明什么。** 单元测试全绿不能替代
   真实素材；真实素材全绿也不能替代"契约没被悄悄改掉"。
2. **默认关闭的正确性用逐字段精确比较证明，不用抽样近似。**
   `decision / reason / delay_ms / delay_samples / shift_samples /
   usable_frames / confidence` 七字段任一不同即记差异。
3. **抽样的层级必须写明采样框。** 哪一层是全量、哪一层是分层抽样、
   为什么抽不起全量，都在 §2.3 写清楚。
4. **不可测不记通过。** 静音轨的残差是 `UNMEASURABLE`，不是 0，也不是 FAIL。

### 8.1 必须说清的一件事：`untouched → anchor` 是报告语义变化

7 条轨从 `decision="untouched"` 变成 `decision="anchor"`（`anchor_role` 为
`secondary`）。它们**没有被移动**（`shift_samples` 仍为 `None`），但
`core/audio_models._row_status` 把 `anchor` 映射成 `ALREADY_ALIGNED`、
把 `untouched` 映射成 `FAILED`。也就是说：**打开分组后，这 7 条轨在状态
报告上从"失败"变成"已对齐"。**

这个映射本身是对的（次级锚点是它所在组的对齐基准，按定义就是对齐的），
但它是开关打开后才有的**可观察变化**，不能藏在"加法"这个词后面。
默认关闭时该变化不发生（A1 = 0 差异）。

另有一条 `20260903_C1167` CH2：`reason` 从 `non_constant` 变为
`recheck_residual`，上报的 `delay_ms` 从 22.98 变为 −0.86 —— 因为它改用了
组内参考（CH1）而不是主锚点（CH3）。该轨最终仍是 `untouched`（复检把它
否掉了），**没有新增也没有丢失修正**。这是"解释换了参考系"，不是行为变化。

产物：`out\ARM_on.json`、`out\cmp_A3A4.json`。

## 14 回归过程中发现并修复的缺陷

这一节是"回归测试确实起作用"的证据 —— 4 个缺陷里有 2 个是**本轮改动引入**的，
2 个是**此前就存在但一直没被发现**的。

### 14.1 音频同步层 import 了元数据层（本轮引入，A.1 FAIL）

`core/channel_sync.py` 在实现透明模式元数据恢复时写了
`from preservation.sony import SonyPreservationBackend`。P4 审计 A.1 的
分层边界禁止音频同步层依赖 Sony/编码/封装库，因此
`test_production_semantics.py` **FAIL 2 条**（A.1 及其控制项 A.C）。

**修复**：把恢复实现整体迁到 `preservation/transparent_restore.py`，
`run_channel_sync` 增加 `restore_metadata` 钩子参数，由调用方（`1kt.py`）
注入。缺钩子时**在动手之前**抛 `ValueError` —— 否则会退化成"交出一个
元数据被剥光的成品"，而那正是本次要根除的缺陷。修复后 63/63 且
`control_failed = 0`。

### 14.2 `start.bat` 的 `SYNC=0` 只关掉一半（既有）

`SYNCARGS` 只在 `SYNC==1` 时拼 `--channel-sync`，但 `--channel-sync-groups`
无条件按 `GROUPS` 拼；而 `--channel-sync-groups` 在 `1kt.py` 里隐含
`--channel-sync`。于是 `SYNC=0, GROUPS=1` 依然会开对齐，而注释却写着
"想关掉就把 SYNC 改成 0"。

**修复**：`SYNC=0` 成为总开关（`GROUPS` 只在 `SYNC=1` 时跟随），
注释同步改正。

### 14.3 `transparent_verify` 的 DJI 分支永远进不去（既有）

```python
from preservation import is_dji_source     # 这个名字不存在
dji = bool(is_dji_source(streams))
except Exception: dji = False              # ImportError 被吞掉
```

后果：每一支 DJI 素材都会被判成"不属于 Sony/DJI 家族"，DJI 验证分支
一次也不会执行，而日志语气正常。**修复**：改用
`core.batch_hw.is_dji_source`（模块顶层早就 import 过，判据是 `djmd` 轨道）。

### 14.4 分组开关在透明模式打印 `threshold=None`（本轮引入）

日志打的是"调用方覆写了什么"，而实际生效的是 DEFAULTS 的 1.30。
运维照着 `None` 排查会走错方向。**修复**：打 `effective_opts` 的生效值，
并把 CLI 是否覆写单列。

### 14.5 顺带纠正的两个测试自身缺陷（不是产品缺陷，记录以免误判）

* `pytest tests/audio_sync_p4` → `no tests ran`（exit 5）：那 7 个文件是
  **独立审计脚本**，各有 `main()`，pytest 收集不到。必须逐个执行。
* 我自己写的损坏输入用例最初让三个变体共用一个输入目录并在变体间清理，

  改成每个变体独立目录后三个变体都正常。

## 17 结论

1. **默认关闭的行为可以认为是未变的**：不是"没看到差异"，而是 226 个片段、
   584 条轨、7 个字段的逐位相等，零差异。
2. **打开开关是加法**：3 条新修正、0 丢失、0 改值；7 个改动文件全部落在
   事先普查出的 7 支可操作片段内。唯一的可观察副作用是 7 条轨的报告状态
   从 `untouched`（`FAILED`）变为次级 `anchor`（`ALREADY_ALIGNED`）——
   已在 §8.1 明确，且默认关闭时不发生。
3. **透明模式的成品是对的**：轨道顺序、`ftyp`、`tref/cdsc`、`nrtm`、
   9 个 uuid box、Gyroflow 的 146146 个 IMU 样本，以及逐轨残差记账 0.0。
4. **`--check` 现在名副其实**：三级真的分级（37 / 45 / 45），`full` 的
   PSNR 单列为 `SKIPPED_NOT_APPLICABLE` 而不是伪造数字。
5. **本轮抓到了 4 个缺陷**，其中 1 个是本轮引入的分层违规、2 个是既有的
   静默失效（DJI 路由、`SYNC=0` 半关）。这比"全绿"本身更有信息量：
   说明这套矩阵对"跑起来不报错但结果不对"这类问题是有检出力的。
6. **不能说的地方已经说清**（§15）：真实编码路径、长片容器层、751 件归档、
   DJI 多轨素材。这些没有被证明，也没有被计入通过。
