# P4.4 — Production Enablement: the validated fixed-delay path

**Status: the validated fixed-delay subset of Audio Sync is ENABLED in
production. Everything unvalidated keeps an explicit boundary.**

```text
Fixed-delay production        ENABLED
D2 gap policy                 DEFERRED
D3 residual acceptance        NOT ESTABLISHED
D5 coordinate contract        DEFERRED
Default path                  UNCHANGED
Drift correction              NOT ENABLED
Resampling                    NOT ENABLED
```

This phase adds **no algorithm**. `core/sync_estimate.py`, GCC-PHAT,
`core/sync_fix.py`, the P1 correction math and the P3.10/P3.11 correction
mechanics are untouched. What it adds is the missing piece between a *correct
measurement* and a *permitted correction*: a single eligibility contract.

---

## 1. Production scope

"Audio Sync" names **three** paths, and P4.4 enables exactly one of them.

| path | grain | entry | state after P4.4 |
|---|---|---|---|
| **P1 fixed delay** `core/channel_sync.py` → `sync_fix.shift_stream` | one integer shift per track | `--channel-sync` / `--channel-sync-transparent` | **ENABLED** — opt-in, now governed by the eligibility contract |
| **P2 constant offset** `core/audio_sync.py` | one integer offset per channel | `--audio-plan` + explicit `sync.reference` | **ENABLED** — opt-in, now governed by the same contract |
| **P4 time-varying** `core/audio_sync_tv.py` | one shift per window | none | **NOT ENABLED** — imported by no production module, asserted by test |

```text
ENSEMBLE: only the validated fixed integer delay is in production.
```

### Why the time-varying path is deliberately still off

`core/audio_sync_tv.CorrectionPlan` takes **`policy=` and `coordinate=` as
constructor parameters**. Routing production through it would decide D2 (gap
policy) and D5 (coordinate contract) as a side effect of wiring — which this
phase's brief forbids and which P4/P4.3 left `DEFERRED` for stated reasons.
So the brief's `CorrectionPlan` box is satisfied by the **fixed-delay plan**
(`core.audio_sync.FixedDelayPlan`), which has no policy and no coordinate by
construction:

```text
measurement -> AudioSyncResult -> evidence validation
            -> production eligibility -> FixedDelayPlan -> PCM apply
```

`FixedDelayPlan.kind == "fixed_integer_delay"`, and its serialised form has no
`policy` or `coordinate` key — so it cannot be confused with the P4 object.

**No new feature flag was needed.** `--channel-sync` / `--audio-plan` already
are the explicit production path, both default OFF and both documented as such;
what was missing was not a switch but a contract.

## 2. Eligibility contract

### 2.1 One decision path

Before P4.4, "may I correct this?" was answered by **each consumer for itself**,
and **none of them looked at the evidence**:

| consumer | decided from |
|---|---|
| `core/audio_timeline._effective_offset` | `status == SUCCESS` |
| `core/audio_sync.apply_sync_result` | `status == SUCCESS` |
| `production/output.apply_alignment` | `status == "success"` |

P4.4 introduces one predicate and makes every consumer call it:

```python
core.audio_models.correction_eligibility(sync, *, application=None, gate=None)
    -> CorrectionEligibility
```

`gate` defaults to the thresholds **reported by the producer**, else to
`core.channel_sync.effective_opts()` — the production effective config. No
threshold is written into the predicate.

### 2.2 The invariant, made structural

```text
eligible is True   =>  offset_samples is an integer, the status is one the
                       state machine permits, and (if the result states
                       evidence) the evidence passes the production gate
eligible is False  =>  offset_samples is None
```

The second line is the whole point. `refused but holding a usable number` is
**unrepresentable**, not merely discouraged. This is requirement U1 —
`number exists == measurement exists` — removed at the type level rather than
by a check a later reader could skip. The number itself is still readable as
`raw_offset_samples`, so a report can say *"measured 480 samples, not used"*.

The same holds for the plan object:

```python
FixedDelayPlan.offsets()        # contains ONLY eligible entries
FixedDelayPlan.refusal_reasons()  # {channel: stable reason code}
```

### 2.3 Supported and unsupported states

| status | value trusted | correction eligible | reason code |
|---|---|---|---|
| `success` | yes | **yes** | — |
| `already_aligned` | yes | no | `sync_already_aligned` |
| `not_processed` | no | no | `sync_not_processed` |
| `not_applicable` | no | no | `sync_not_applicable` |
| `low_confidence` | no | no | `sync_low_confidence` |
| `non_constant` | no | no | `sync_non_constant` |
| `out_of_range` | no | no | `sync_out_of_range` |
| `recheck_failed` | no | no | `sync_recheck_failed` |
| `failed` | no | no | `sync_failed` |

Every reason code is **derived from `SYNC_STATUS_PATH`**, the state machine
P4.3 introduced; a test asserts the two tables have exactly the same members, so
a new status cannot be added without an eligibility answer.

Additional refusals, independent of status:

| condition | reason code |
|---|---|
| no offset present | `sync_offset_missing` |
| NaN / infinite / beyond the ±2³¹ shift guard | `sync_offset_invalid` |
| evidence stated and below the production gate | `sync_evidence_insufficient` |
| the caller asked for `SyncApplication.NONE` | `sync_application_none` |

`already_aligned` being ineligible is **not** a distrust: the value is trusted,
there is simply no correction to apply.

### 2.4 "Not stated" is not "insufficient"

```text
coverage is None   ->  evidence_checked = False, the verdict is unchanged
coverage is stated ->  compared against the gate the REPORT names
```

This is D1's backward-compatibility rule, carried into eligibility: adding a
field must not retroactively fail a historical record. Measured on the frozen
P1 corpus: **548 rows replay with 0 changed conclusions, and all 11 frozen
`fixed` rows remain eligible**.

The distinction is real, and the same row shows both readings: with coverage
**not stated** it is eligible (historical); with the coverage a re-checked
producer would have written (5/20 = 0.250) it is **refused**. Both directions
are asserted.

## 3. Fail-closed behaviour

```text
missing evidence          ->  refused, reason named, NO offset returned
insufficient evidence     ->  refused (sync_evidence_insufficient)
LOW_CONFIDENCE            ->  refused (sync_low_confidence)
UNRESOLVED_GAP            ->  cannot claim TRUSTED at all; refused
invalid state             ->  refused (sync_status_unknown)
invalid offset            ->  refused (sync_offset_invalid)
invalid timeline / plan   ->  the existing error model raises (unchanged)
```

Nothing guesses. A refused correction reaches the bytes: an ineligible result
produces output **bit-identical to the source** (asserted in the static audit's
behavioural half, not merely argued).

## 4. Default path

```text
no --channel-sync, no --audio-plan  ->  audio handled exactly as before
```

Measured rather than asserted: with every PCM entry point instrumented
(`run_channel_sync`, `estimate_sync`, `apply_sync_result`, `resolve_timeline`,
`AudioPCMReader`), a production call with no audio plan performs

```text
PCM/sync calls : 0
wall time      : 0.057 ms
file touched   : no
```

`produce_audio_output(plan=None)` returns before constructing a reader, a
timeline or a plan. The eligibility predicate costs **≈2.1–2.3 µs per call** and
is not reached at all on this path.

## 4a. Real-material verification

The real production call (`run_channel_sync`, reached from `1kt.py`) over the
retained real A7M5 known-answer material, with the result verified
**independently** of the code that produced it — an integer cross-correlation
written in the harness, not `core.sync_estimate`:

| case | injected | eligible (applied) | refused | independent residual |
|---|---|---|---|---|
| `p1_kat_two_sided.mp4` | `[0, +1200, 0, −600]` | `CH2 → +1200`, `CH4 → −600` | CH1, CH3 `already_aligned` | corrected tracks **+0 samples**, corr 1.0 |
| `p1_kat_constant_1200.mp4` | `[0, +1200, 0, 0]` | `CH2 → +1200` | CH1, CH3, CH4 `already_aligned` | corrected track **+0 samples**, corr 1.0 |
| `p1_kat_aligned.mp4` | `[0, 0, 0, 0]` | none | all four `already_aligned` | n/a — zero offset is an identity |
| `p1_kat_silent.mp4` | one silent track | none | CH4 `sync_failed`, rest `already_aligned` | n/a |

In every case: `decision == "fixed"` **iff** the row is eligible; no non-fixed
row carries a `shift_samples`; the source files are byte-unchanged.

```text
positive offset   covered (CH2, +1200 samples)
negative offset   covered (CH4, -600 samples)
zero offset       covered (p1_kat_aligned: nothing applied at all)
multiple channels covered (4 mono streams in every case)
```

Residual tolerance is **derived**, not chosen: `verify_max_ms` from
`core.channel_sync.DEFAULTS`, converted at 48 kHz and rounded up → 3 samples.
The measured residual is 0.

## 5. Known limitations

| limitation | status |
|---|---|
| the eligibility contract does not state a **residual** acceptance threshold | **D3 `NOT ESTABLISHED`** — no threshold was invented; eligibility rests on the evidence gate, not on a residual bound |
| the correction is **lagging or anticipating** depending on the coordinate contract | **D5 `DEFERRED`** — `latest-start` remains the implementation default for reproducibility, not a frozen semantic contract |
| nothing decides what a gap should contain | **D2 `DEFERRED`** — no gap policy is selected, and the fixed-delay path has no gaps to fill |
| the plan-window population is still not representable on `AudioSyncResult` | open, owner D8 (P4.3's `T5.4b`) |
| the enabled path measures **every** stream, including tracks it then refuses | measured on a real 4 s 4-mono C1305 clip: **1.234 s wall (0.308 s per source second)**, traced peak **13.15 MB**, RSS delta **+65.9 MB**. The clip's own result was `measure_failed` with three of four tracks refused — an honest outcome on coverage-limited material, and the reason the cost is stated per source second rather than as a per-file constant |
| the enabled path's memory is **not** the P4 figure | P4 measured the plan/applier path (`core/audio_sync_tv`) at 9.10 MB peak. `run_channel_sync` is a different path with a **1.44 M-sample (30 s @ 48 kHz) anchor segment** per estimate; the two numbers are not comparable and neither is quoted as the other |
| `tests/audio_sync_p311/test_coordinates.py` | **BLOCKED — environment** (machine memory), in P3.11 research code this phase never touched |
| `work/p3/p37/known_truth.py` | **FAIL (21 cases), pre-existing and not attributable to this phase** — it imports nothing from the repository; re-run from an isolated copy of `work/p3/p37` it reproduces identically. Its `current` row differs from the summary table in `gap-policy-decision.md` §3.2, which records `current` as 132/132 correct on the state sequence; this is a P3.7 bookkeeping discrepancy of the class already registered in `evidence-freeze.md` §7b. **No conclusion is drawn about `current`**, and P3.7's frozen research was not edited |

## 6. Where the contract lives

| artefact | role |
|---|---|
| `core.audio_models.SYNC_STATUS_PATH` | which states may correct (the table) |
| `core.audio_models.correction_eligibility` | **the** predicate |
| `core.audio_models.CorrectionEligibility` | the verdict; carries no offset when refused |
| `core.audio_sync.FixedDelayPlan` / `FixedDelayEntry` | the plan a consumer acts on; ineligible entries carry no offset |
| `core.audio_sync.PairSyncEstimate.eligibility_reason` | why a target was refused, on the estimate itself |
| `production.output.AlignmentOutcome.evidence[...]` | `eligible` / `eligibility_reason` per channel |
| `1kt.py --channel-sync` / `--audio-plan` | the explicit, opt-in production entry |

Test suites: `tests/audio_sync_p4/test_production_eligibility.py` (E1–E10 plus
the plan invariant, the single-decision-path check and the producer/consumer
agreement), and the audits under `work/p4.4/`.
