> 窗口：2026-11-19 08:00–20:00（12 h）
> 硬约束：**12:00 前不启动任何 NVENC 编码任务**；用户另有任务运行到约 12:00。
> 目标：在可用时间内跑完所有可执行的编码矩阵，并产出与 2026-11-18 数据可直接对比的报告。

## 0. 12:00 前的硬性规则

- 08:00–12:00 只允许：**QSV HEVC、QSV AV1、x265、SVT-AV1、对齐/单元测试中的非 NVENC 部分**。
- 禁止：`--encoder nvenc`、`--encoder nvenc-av1`；也避免运行会主动探测/初始化 NVENC 的脚本。
- 08:00 启动前确认：用户任务正在运行、GPU NVENC 占用情况；不结束、不暂停用户任务。
- 12:00 后先确认用户任务结束（或至少 NVENC 空闲），再启动 NVENC 矩阵。

- 两个长片 C0070/C0524：非矩阵，预计数小时，需单独窗口，不塞进本轮。

## 5. 通过标准

- 所有计划内 cell `rc=0`，输出可解码；
- 格式：HEVC 保源/按 caps 降级，AV1 统一 420/10，硬件 8-bit 真实输出 8-bit；
- 元数据：能跑的部分保持 `--preserve-metadata` / `--no-metadata` 语义（真实 E2E 仍 BLOCKED）；
- 报告含：逐片段率-质量、QSV ICQ 对比、撞墙、速度、与 11-18 的交叉校验；
- 归档 SHA256 全部通过。

## 6. 风险

| 风险 | 处理 |
|---|---|
| 用户任务到 12:00 仍未结束 | QSV/软件继续，NVENC 继续等待；不抢 GPU |
| 软件 morning 受用户任务 CPU 影响变慢 | 优先保证 x265 FAST/HQ；SVT 可移到 12:00 后 |
| 硬件矩阵超过 15:45 | 砍 SMALL/UHQ，保 FAST/HQ；报告标注 |
| x265 UHQ 样本超时 | 直接跳过，不挤占分析/报告 |
| 真实语料缺失 | 元数据 E2E 标 BLOCKED，不伪造通过 |
| 磁盘不足 | 开跑前检查 ≥80 GB；输出按需清理 `.1ktwork` |
