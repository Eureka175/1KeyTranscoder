The two definitions:

| | expectation derived from | who can see it | result for `current` | result over all cases |
|---|---|---|---|---|
| **1a** | the **measurement mask** (`valid` / `delay_samples is not None`) | the policy **cannot** — it is the independent oracle | **1/22** | **111/132** |
| **1b** | the **policy's own claimed mask** (`plan.resolved`) | the policy itself | **22/22** | **132/132** |

### 1b is satisfied by construction, so it cannot detect anything

The engine defines the state as a pure function of the policy's own claim
(`semantics.py`, `GapPlan(policy, shift, resolved, derive_states(resolved), …)`).
Seeding the expectation from that same claimed mask therefore compares a claim
with itself. Measured:

```text
cases where state == derive(own claimed mask) : 132/132
```

This holds for **every** policy, including `current`. **A consistency check that
compares a claim to itself can never detect an over-claim**, which is precisely
what this check exists to detect (its own module docstring says so: *"This is the
check that would catch a policy inventing knowledge: if it reported a refused
window as TRUSTED, the state sequence would disagree with a mask-derived
expectation."*). The `132/132` figure is therefore a real computation, but it is
not evidence about over-claiming.

### The documents' quoted output block is a 1b block

`gap-policy-decision.md` §3.2 and `safe-gap-design.md` §8.2 both quote:

```text

no fake TRUSTED window in any case      : True
`resolved` flags correct in every case  : False
```

The unchanged reproducer prints `False / False / False`. Recomputing the same
three lines under definition 1b yields **`True / True / False`** — an exact match
for the quoted block. The quoted block therefore did not come from
`known_truth.py` as it stands.

## 5. Confirmed root cause

**The same check name was computed under two different definitions, and the
aggregate that reached the documents is the one that cannot fail.**

The mechanism, in the source:

```python
# work/p3/p37/semantics.py, end of decide()
if policy == "current":
    resolved[:] = True

return GapPlan(policy, shift, resolved, derive_states(resolved), acc, runs, ...)
```

`current` marks **every** window — including refused ones — as backed by a
measurement. `derive_states` is a pure function of that mask, so with an all-true
mask every window is labelled `TRUSTED` and no window is ever `UNRESOLVED_GAP`.
Measured consequence over the 22 `current` cases: **195 refused windows labelled
`TRUSTED`**, in 21 of 22 cases; the single exception is the gap-free pairing
`G0_no_gap`, where there is nothing to over-claim — which is exactly why the row
is `1/22` and not `0/22`.

So the `current` row is not a near-miss. Under the independent oracle it fails
the state-sequence check, the fake-`TRUSTED` check **and** the `resolved` check,
all in 21 of 22 cases. The documents' reassurance that `current` scores
`132/132` with **`0` fake `TRUSTED`** is not supported: that claim is false under
1a, where the count is **195**.

This also explains the frozen artefact's **internal** contradiction, which is
part of the finding and was **not** edited:

```text
known_truth_matrix.json stores   state_sequence_correct_everywhere = false
                                 no_fake_trusted_everywhere        = false
its own note field asserts       "A policy can pass the first two and fail the
                                  third -- that is exactly `current`."
```

The note describes the `1b` picture; the data in the same file is the `1a`
picture.

### Classification against the eight candidate causes

| # | candidate | verdict | evidence |
|---|---|---|---|
| 1 | fixture construction error | **rejected** | the mask declared by the case equals the mask derived from its records, in all 132 cases |
| 2 | expected-state generation logic error | **rejected** | two independent implementations of the mask-derived expectation agree in **22/22** pairings |
| 3 | statistics denominator / index error | **CONFIRMED (primary)** | `132 = 6 x 22`; one name, two definitions; the all-case aggregate is `111/132`, not `132/132` |
| 4 | checker assertion error | **rejected** | the reproducer's per-case counts reproduce exactly and were independently reconfirmed case by case |
| 5 | documentation summary error | **CONFIRMED** | the documents record 1b's numbers against the 1a question, and quote a `True/True/False` block the reproducer does not print (identical to a recomputed 1b block) |
| 6 | script and document used different data versions | **partially — different *definitions*, not different data** | the artefact is deterministic and regenerates byte-identically; the divergence is 1a vs 1b |
| 7 | genuine semantic implementation difference | **no** | source behaviour is deterministic and self-consistent; the disagreement is about where the *expectation* comes from, not about observed behaviour |

## 6. Corrected interpretation

**Both statistics are kept, each labelled. Neither is dropped, and the
better-looking one is not selected.** They answer different questions:

* **`111/132` (check 1a)** — does the policy's reported state sequence agree with
  what the *measurements* support? This is the discriminating check, and it is
  the one the check was designed to be.
* **`132/132` (check 1b)** — is the policy's reported state sequence consistent
  with its own claimed mask? This is a tautology for every policy and carries no
  information about over-claiming.

The substantive finding **does not change in kind but is larger in extent** than
the documents stated:

* Unchanged: `current` **over-claims** — the correct characterisation remains
  *"`current` claims more knowledge than the evidence supports"*, a **semantic
  over-claim, not an algorithmic error**. `current` is the *reference* model of
  the shipped P3.6 `INVALID_EDGE` behaviour, which has no uncertainty channel at
  all: it emits a number for every window and has no way to say "this number is
  not backed by a measurement". Modelling that as `resolved = True` everywhere is
  faithful; labelling every window `TRUSTED` is its direct consequence.
* Corrected: it is **not** true that `current` passes the state-sequence and
  fake-`TRUSTED` checks and fails only the `resolved` check. Under the
  independent oracle it fails all three, in 21 of 22 cases, and labels **195**
  refused windows `TRUSTED` rather than `0`.
* Unchanged: no policy alters an accepted measurement
  (`n_trusted_windows_altered = 0` everywhere). This is about *claimed knowledge*,
  not about changed numbers.
* Consistent with the P4 line: this is the same defect class P4.2 fixed in
  production — `ADOPTED_RESULT_MUST_SATISFY_GATE`, and the requirement U1 that
  *"a number exists"* must not be read as *"a measurement exists"*. The P3.7
  matrix measures that distinction in a research harness; P4.2 removed the live
  instance of it from `core/channel_sync.py`.

**No product decision is made here.** `D2` remains `DEFERRED`, exactly as P4.3
and P4.4 recorded. Nothing in this audit selects a gap policy or changes the
default, and no file under `core/`, `production/` or the estimator was touched.

## 7. Remaining uncertainty

Stated explicitly rather than resolved by assumption:

1. **Which definition the P3.7 author intended is not established.** The P3.7
   report's table is internally mixed (`22/22` in a row whose header implies the
   all-case aggregate). Evidence supports "the quoted block is a 1b block" as a
   measurement; it does **not** establish intent.
2. **Whether `known_truth.py` was changed after the P3.7 report was written
   cannot be decided.** The research tree lives under the git-ignored `work/`
   directory, so it has **no version history**. There is no artefact that could
   distinguish "the script was strengthened later" from "the report was written
   from a different computation". This is recorded as undecidable, not guessed.
3. **P3.8 had already reached the same conclusion**, in
   `work/p3/p38/agent_a/report.md` §4 and `proposals.md`, where the 1a/1b
   distinction is computed and the cause named. That analysis stayed inside the
   git-ignored research tree and never reached `docs/`, so the P4 documents
   inherited the uncorrected figure. P4.5's contribution is therefore
   **independent confirmation, promotion into `docs/`, a case-level export, and
   a permanent guard** — not first discovery. Recorded so the provenance is not
   overstated.
4. **No historical report was rewritten.** `work/p3/P3.7-SAFE-GAP-DESIGN-REPORT.md`
   is untouched, the frozen `known_truth_matrix.json` is untouched (and verifiably
   regenerates byte-identically), and the `132/132` figures remain visible in the
   documents that carry them, now labelled with the definition they belong to.
