## 1. What this phase is

P3.10 proved the chain

```text
production measurement -> production plan -> ACTUAL PCM apply -> independent re-measurement
```

on **one** channel pair per corpus (`ch3_to_ch4`). P3.11 asks whether it generalises to the
**whole** pair set, and what the coordinate and gap-policy choices actually do to real PCM.

The single core question:

> Can P3.10's real `measure -> plan -> apply -> independent verify` be reproduced on the other
> real channel pairs of C1305/C1306, and what does each coordinate / gap-policy candidate
> produce on real PCM?

No policy is selected. No threshold is defined.

## 5. Geometry, asserted rather than assumed

```text
sample rate   48 000 Hz, float32, 1 channel
window        1 440 000 samples = 30.0 s
hop             480 000 samples = 10.0 s
search        ±3 000 samples = 62.5 ms
residual grid 5 s window, 10 s hop (aligned to the correction block boundaries)
```

`measure_resumable.py` asserts `n_win == 1_440_000`, `hop == 480_000`, `search == 3000`, so a
silent default change cannot make the phase measure something else.

## 6. The seam, stated once

```text
measurement windows = floor((n - win)/hop) + 1
applier blocks      = ceil(n / hop)
```

With `win = 3*hop` these differ by **2 when `n mod hop == 0` and 3 otherwise** — measured on a
`k*hop` sweep in `tests/audio_sync_p311/test_coordinates.py`, not reasoned about. An earlier
draft of the same docstring claimed the opposite ("3 exactly when `n mod hop` is 0"); the sweep
is what settled it. Both corpora have `n mod hop ≠ 0` (350 520 and 223 704), which is why both
give 3.

The seam is a function of `(n, win, hop)` **alone**: identical for every target, every pair and
every policy, because a complete run always resolves the same window count. It is arithmetic,
not a per-pair defect. For `n` shorter than one window the measurement formula goes **negative**
(`n = hop + 1` → `-1`), which is a domain error rather than a seam, and the driver prints the
computed value instead of assuming it.

The seam is closed only by declaring the tail blocks `valid=False`
(`reason="not_measured_no_full_window"`), which the mask can express and which the state
sequence records. Never by padding, truncating or repeating a shift.

## 7. Sign convention

`shift = +rint(delay)`, `out[n] = in[n + shift]`, so a correct correction leaves the measured
delay at 0. Settled empirically in P3.10 by applying each candidate shift to a pair whose target
is exactly 120 samples late and reading what the estimator then reported
(`work/p3/p310/sign_fixture.py`, `sign_after_shift.py`). P3.11 did not re-derive it and did not
change it.

```text
residual_after      = the delay the estimator reports for the CORRECTED PCM
expected_residual   = measured_before - applied_shift
excess              = residual_after - expected_residual
```

## 8. Coordinate contracts — measured, not asserted

| contract | mapping | status |
|---|---|---|
| `latest-start` | `w = pos // hop` | **what `apply_shift_plan` computes** |
| `nearest-centre` | `w = (pos - win/2 + hop/2) // hop` | observed only, **not selected** |
| `sample-domain` | the latest window whose measurement window covers the sample | **not a third candidate — identical to `latest-start`** |

Two facts about this comparison were established by measurement and are load-bearing:

1. **`sample-domain` is not an independent implementation.** Measurement windows are 30 s on a
   10 s hop and therefore overlap; three of them cover any sample, and the latest covering index
   is `pos // hop`. `test_coordinates.py` asserts the identity on every fixture and on both
   production plan sizes.
2. **At `win = 2*hop` the two distinct contracts are the same function.** The window centres sit
   `1.5*hop` apart, so the midpoint between two centres lands exactly on a hop boundary and the
   tie-break decides. `diag_ratio.py` measures the transition: ratio 2 → 0 samples differ;
   ratio 3 → 91.67 % differ. The adversarial fixtures therefore run at **`win = 3*hop`**, the
   production coefficient, because a fixture at ratio 2 is structurally unable to distinguish
   the contracts it is supposed to test.

### Two agreement figures, both reported

| quantity | C1305 (ch3→ch4) | C1306 (ch3→ch4) |
|---|---:|---:|
| window **index** agreement | 0.21 % | 0.24 % |
| applied **shift value** agreement | **56.94 %** | **36.37 %** |
| produced shift-change zones | 73 | 63 |
| first value disagreement | 20.0 s | 20.0 s |
| max shift difference | 732 samples | 211 samples |

P3.10 reported the **value** figure (57.17 % / 36.69 %, 73 / 63 zones) and P3.11 reproduces it,
within a couple of tenths of a percent and with the identical zone count. The **index** figure
is what the coordinate *contract* is about, and at `win = 3*hop` the two mappings differ by one
index for every block past the first three, which is why it is near zero. Neither figure
substitutes for the other; the earlier field name `max_abs_positional_difference_samples`
described an index difference in sample-like units and has been renamed
`max_abs_index_difference`.

Full comparison: `work/p3/p311/coordinate/`, `work/p3/p311/reports/coordinate-comparison.md`.

## 9. Gap policies — the mask is shared, only the fill changes

Every arm reads the **same** measurement records, hence the same resolved mask; the coordinate
is fixed to `latest-start` for this comparison so that a coordinate effect cannot be confused
with a gap-policy effect.

| policy | meaning | offline only |
|---|---|---|
| `current` | forward carry; a leading gap takes the first trusted value after it. Reports gap windows as TRUSTED — the P3.7 over-claim, reproduced deliberately | no |
| `hold` | forward carry; nothing to carry → 0 | no |
| `no_correction_gap` | 0 across every gap | no |
| `explicit_state` | identical SHIFT to `hold`; the state is made first-class | no |
| `linear` | interpolate between the bounding trusted values | **YES — reference only, not a candidate** |
| `next` | bounded by the next trusted value | **YES — not run here** |

`POLICY = DEFERRED`. No ranking, no recommendation, no winner.

## 10. Defects this phase found in its own code

Recorded because the pattern in this research line is that the defect lives in the checker.

| # | defect | how it surfaced | fix |
|---|---|---|---|
| 1 | `coord_labels` evaluated the mapping at window starts while the apply path evaluated it per sample, so the two disagreed on every block | `test_coordinates.py` T1 | evaluate at block starts; T1 now asserts equality |
| 2 | `window_nearest_centre` **clipped** the negative index for block 0, which made the candidate byte-identical to `latest-start` for small plans — a comparison that cannot show a difference | T3 | clipping made explicit and part of the contract; the raw mapping returns `-1` |
| 3 | the claim "sample-domain subtracts `win/2`" was wrong; overlapping measurement windows make the covering window `pos // hop` | T4, after the arithmetic was done properly | identity asserted on every fixture |
| 4 | the adversarial fixtures ran at `win = 2*hop`, where the contracts cannot differ | the discrimination check refused to pass | geometry moved to `win = 3*hop`; `diag_ratio.py` documents why |
| 5 | the `current`-policy state expectation in the fixture suite was hand-waved | the suite failed | expected sequence is all-`T`, which IS the over-claim |
| 6 | `residual_stats` iterated the dict it was mutating and tried to multiply a nested dict by a float | `TypeError` on the first real run | built from a snapshot |
| 7 | `tail_direction` reported `IMPROVED` for median, p90, p95, max and mean **simultaneously on an empty set** | visible in the smoke run's output | returns `INSUFFICIENT_DATA`; `verify` exits 3 when either side has no valid point |
| 8 | the contract check read both whole streams into memory (2 × 880 MiB, peak RSS 3 632 MiB) | peak-RSS report | chunked; one block of each stream resident |
| 9 | `peak_rss_bytes` returned a plausible small number because the struct field widths were not asserted | a positive control (commit 800 MB, expect ~800 MB) read correctly only after the fix | `SIZE_T` asserted, `restype`/`argtypes` set, `-1` on failure |
| 10 | a hard-coded four-policy list **shadowed** the engine's `POLICIES` import, so the `linear` reference arm died in argparse and was silently absent from the comparison | a missing artifact | choices derived from the engine |
| 11 | `cmd_apply` wrote the corrected PCM to a path with **no coordinate component** while `cmd_verify` read that same path: each arm measured its own file correctly, but successive arms overwrote each other, so no arm's stream could be re-checked afterwards | a hash check against disk | per-coordinate output directory; `coordinate_dirname()` |
| 12 | adding the coordinate component to the output path broke the write, because `apply_shift_plan` opens the destination with `open(dst, "wb")` and that does **not** create parent directories | `FileNotFoundError` on the first re-run | `dst.parent.mkdir(parents=True, exist_ok=True)` before the engine call |
| 13 | the apply metadata was written to `<stem>/` while the corrected PCM went to `<stem>/<coordinate>/`, so `run_comparison.py` looked for metadata that was never there | `FileNotFoundError` after a **successful** apply | metadata written to the same per-coordinate directory |
| 14 | the `probe` subparser had no `--coordinate` argument, so the last stage of the chain died with `AttributeError: 'Namespace' object has no attribute 'coordinate'` **after** plan, apply and verify had all succeeded | the stage order hid it until the final step | `--coordinate` added to the probe parser |
| 15 | two batches were launched concurrently and both wrote `<stem>/<coordinate>/<pair>_hold_corrected.f32`, i.e. they interleaved writes to the same 880 MB stream | a downstream reader could not find the file | batches serialized: stage A, then stage D, then stage C, one at a time |

Items 11–15 are all the same shape: a **path or lifecycle** defect that produces no wrong
number but makes the phase's outputs unreproducible or non-addressable. None of them falsified a
measurement — every recorded result was measured against a file that was correct at the moment
it was read — and all of them would have prevented a reader from re-checking the result unaided.
The comparison batches were re-run in a serialized order after the fixes, and
`check_reproduction.py` confirms the two independent stage-A / stage-D runs of the shared arm
produce the identical corrected PCM and the identical statistics on all six pairs.

Item 11 is the one worth restating plainly: **every recorded result was measured against the
correct stream** — `run_comparison.py` reads the apply metadata immediately after its own apply —
but the streams were not retained, so a reader could not re-verify them. That is a real
reproducibility defect in a phase whose purpose is independent re-checkability, and it is why the
comparison batches were re-run with the per-coordinate path. `check_reproduction.py` compares the
two runs of every shared arm on corrected-PCM hash and on before/after medians.

## 11. Archive pass

P3.11's real apply stage writes a full-length float32 stream per arm: 66 streams, 52.94 GiB
across the three batches. All of it was handled by the repository's MOVE-ONLY convention:

| tree | files | GiB | disposition |
|---|---:|---:|---|
| `work/archive/pending-delete/p311-apply-pcm/` | 54 | 43.32 | **held for review** — other policies' and probes' streams, reproducible from the plan `.npy` plus the raw corpus |
| `work/archive/pending-delete/p311-apply-pcm-superseded/` | 96 | 48.13 | registered in full, then **reclaimed** (see below) |
| kept in place under `work/p3/p311/apply/` | 12 | 9.63 | the two stage-A/stage-C arms' `_hold_corrected.f32` per pair, which the phase's evidence names |

The held tree has a row per file carrying original path, size, SHA-256 and a copy-pasteable
restore command: `work/archive/P311-ARCHIVE-MANIFEST.md` and
`work/archive/p311-archive-manifest.json`.

**The superseded tree, and why space had to be reclaimed.** The first apply layout omitted the
coordinate from the output path (defect 11), so after the re-run its 48.13 GiB was pure
redundancy: byte-identical in content to streams kept under the current layout, and referenced
by nothing — verified by searching every P3.11 script, report and evidence record. The volume
was down to **2.1 GB free**, which is a real hazard for any later run, and the files in it were
created by P3.11 itself earlier in the same session.

So they were handled in the order the convention requires: **registered first**, one row per
file with path, size and SHA-256, in `work/archive/P311-SUPERSEDED-PCM-REGISTER.md` and
`.json`; only then removed, by `register_superseded.py --reclaim`. That recovered 48.13 GiB
(2.1 → 50.2 GB free).

No pre-existing user file, no earlier phase's artifact, and nothing in the retained evidence set
was touched at any point. See also the standing `work/archive/QUARANTINE-REGISTER.md`.
