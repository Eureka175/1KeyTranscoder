# P3.12 provenance — adaptive coarse-to-fine measurement

This document pins the identity of the P3.12 study, per the requirement that the algorithm must
not live in `work/p3/p312/` without an identity record. Machine-readable form:
`work/p3/p312/provenance.json`.

## 1. What this phase is

The hypothesis:

> A low-cost coarse pass over the whole timeline, followed by recursive refinement **only** in
> time intervals showing a delay change, ambiguity, low confidence or unresolved state, can
> reduce the number of estimator calls **without missing any real delay transition**.

The single question:

> Can adaptive time-interval refinement reduce estimator calls without missing a real delay
> transition?

**Answer: MISSED_TRANSITION = 0 on known ground truth, but estimator calls rose by 2–10×, so
`NO ADVANTAGE DEMONSTRATED`.**

## 3. The refinement axis, and what is excluded

```text
refined:  TIME INTERVAL
never:    the delay value axis. [-3000, +3000] is NOT bisected.
```

The GCC/PHAT correlation surface is not monotone in lag, so a bisection over lag would be
invalid. The algorithm contains no search over lag.

Excluded by design: machine learning, Bayesian model, dynamic programming, neural network.
Excluded by scope: PCM apply, the coordinate contract (`latest-start` / `nearest-centre` /
`sample-domain`), fractional correction, resampling, a second measurement geometry.

## 4. Algorithm versions

| version | structure | result on the fixture set |
|---|---|---|
| `p312-adaptive-1` | four interior point probes per node (`L/4`, `L/2`, `3L/4`, `hi-1`) | **MISSED = 2**, 634 calls |
| `p312-adaptive-2` | dense half-length window grid on four phase offsets, plus edge windows, plus a per-root phase offset | **MISSED = 0**, 1126 calls |

v2 is the shipped version. The difference between them is the phase's central finding about the
algorithm: two agreeing half-windows cannot see a change that sits exactly on their shared
boundary, and v1's repair — a probe centred on the boundary — measured the wrong place because
`_window_for` right-aligns a window inside a span. A change on the *outer* edge of a root is
invisible to every root's interior grid, which is why v2 adds explicit edge windows.

## 5. Research thresholds

Every one is in `AdaptiveConfig` and is written verbatim into each artifact. None is a production
threshold and none is read from production.

| field | default | role |
|---|---:|---|
| `coarse_interval_s` | 60.0 | root interval length |
| `leaf_window_s` | 10.0 | measurement window length at a leaf |
| `min_interval_s` | 7.5 | smallest interval the recursion may produce |
| `max_depth` | 3 | recursion depth cap |
| `max_calls_per_pair` | 20 000 | hard estimator-call budget |
| `abs_tol_samples` | 8.0 | absolute consistency floor |
| `rel_tol_uncertainty` | 3.0 | consistency tolerance as a multiple of reported uncertainty |
| `min_peak_over_noise` | 6.0 | matches the shipped gate |
| `max_second_peak_ratio` | 0.85 | ambiguity trigger |

**`abs_tol_samples` is the one constant that is neither a production threshold nor derived from
one**, and it is not a free parameter: `resolution_floor.py` shows a leaf is acceptable only when

```text
slope * leaf_seconds  <  abs_tol  <  smallest real step
```

i.e. `0.5 * T < abs_tol < 160` on this fixture set. The default 8.0 lies inside that band. It is
swept in `sensitivity.py` and the results are sensitive to it, so it is recorded as a
**research constant that is not solved**, not as a calibrated value.

## 8. Result, with both baselines

Estimator calls are counted by `engine.Engine`, not inferred.

| run | calls | exhaustive (10 s grid) | ratio |
|---|---:|---:|---:|
| synthetic, v1 | 634 | 480 | 0.76 |
| synthetic, v2 | 1126 | 480 | **0.43** |
| C1305 CH3→CH4, v2 | 5164 | 478 | **0.093** |
| C1306 CH3→CH4, v2 | 4091 | 414 | **0.101** |

Where both methods resolve a block, the delays agree to **1.365 samples** (C1305) and
**1.563 samples** (C1306). The small "both resolved" counts (40 and 86) are not a disagreement
about values: they are a disagreement about *which* blocks each method resolves. The adaptive
method resolves 42 and 88 blocks; the reference resolves 247 and 308. The adaptive method spends
its calls on **more coverage than the reference grid has**, which is still a loss on the metric
the brief cares about.

A ratio below 1.0 means the adaptive method made **more** calls than measuring every block. Against
the coarse-resolution baseline (one call per 60 s) the ratios are 0.07–0.13, i.e. an order of
magnitude worse. Both baselines are reported because quoting only one would let a large loss be
presented as a gain.

**Cause, measured:** on C1305 CH3→CH4 the recovered delay across 16 consecutive 10 s probes runs
495–727 samples with 10–50 sample steps between neighbours. The delay changes on a timescale
shorter than the 60 s coarse interval, so no root is ever accepted and the tree subdivides
everywhere. At 10 s resolution the exhaustive grid has no redundancy to remove.

## 9. Safety

`MISSED_TRANSITION` = a `TRUSTED` leaf that straddles a sample where the true delay changes by
more than the transition floor.

| run | MISSED |
|---|---:|
| v1 | 2 (S4, S7) |
| **v2** | **0** |

Two limitations remain, both with measured bounds:

1. a transition within **one sample** of a leaf edge is reported as straddled even though both
   sides carry the correct delay (adversarial A02);
2. any excursion **shorter than the measurement window** is averaged into that window's single
   estimate and cannot be seen at any refinement depth (adversarial A04). Refinement changes where
   windows are placed, not how long they are.

## 10. Validation

| suite | result |
|---|---|
| construction vs independent FFT | 25/25 |
| generator selftest | 37/37 |
| synthetic fixtures, v2 | MISSED 0, UNCOVERED 2, 1126 calls |
| adversarial (12 cases) | 29 PASS / 4 FAIL, all four being the two documented limitations |
| chunk invariance | PASS for admissible partitions **with a half-window halo** |
| reproducibility | PASS on tree digest, call count, delays, states, content digest |
| sensitivity | **5 of 7** configurations measured; best saving 12 %; the two unmeasured configurations vary only `max_depth` and are named as not measured in `sensitivity.json` |

**Chunk invariance found an interface requirement, not a bug.** A window straddling a chunk
boundary is precisely what detects a change at that boundary, so a chunked driver must read
`half_window` beyond its own span. The first version of the test handed each chunk only its own
slice, silently truncating a 10 s window to 5 s. Partitions whose interior bounds are not
coarse-interval multiples are marked NOT APPLICABLE with the reason, because they change the root
grid and would test the driver rather than the algorithm.

## 11. Defects found in this phase's own code

Fourteen, enumerated in `failure-analysis.md`. The two that matter most were both in the safety
metric:

* the first `MISSED_TRANSITION` asked whether the true delay varies inside a reference block. A
  perfect step makes every block internally constant, so it **could never fire** while reporting
  zero misses on a fixture with a 320-sample step;
* the corrected version then counted an edge-aligned step as a miss, and the correction to that
  counted a step one sample before a boundary as a miss.

The index arithmetic is now stated as an identity (`s + 1 < hi`) rather than an inequality, with
both failure modes recorded at the site.
