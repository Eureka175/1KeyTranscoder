  这个压缩包解压出来就能用。不需要 Python，不需要联网，不需要安装任何东西。


================================================================================
  0. 一句话说明这是干什么的
================================================================================

  它跟着你的生产转码器一起跑，把生产转码器**实际算出来的、实际决定的**东西
  如实记下来，存成文本数据。

  它不转码、不解码、不跑 ffmpeg、不重试、不改任何参数。
  它失败不影响你的转码 —— 最坏情况只是"这一个月的数据缺一部分"。

  一个月之后，把数据拿回开发机分析，用来优化 x265 参数和 scaling。


================================================================================
  1. 三步跑起来
================================================================================

  ┌─ 第 1 步 ────────────────────────────────────────────────────────────────┐
  │ 整个文件夹解压到长期那台机器上，比如：                                    │
  │                                                                          │
  │     D:\1kt\collector\                                                    │
  │                                                                          │
  │ 解压后应该是这样：                                                        │
  │                                                                          │
  │     D:\1kt\collector\                                                    │
  │       QUICKSTART.zh-CN.txt          <- 你正在看的这份                    │
  │       README.txt                    <- 完整英文文档，细节更全             │
  │       x265-calibration-collector.exe<- 采集器本体，唯一要跑的程序         │
  │       START-COLLECTOR.bat           <- 双击启动                          │
  │       CHECK-INSTALL.bat             <- 双击自检                          │
  │       INSTALL-SCHEDULED-TASK.bat    <- 双击注册开机自启                   │
  │       UNINSTALL-SCHEDULED-TASK.bat  <- 双击取消开机自启                   │
  │       schema.json                   <- 事件格式定义（备用）               │
  │       collector.toml                <- 可选配置                          │
  │       VERSION / SHA256SUMS.txt      <- 版本和校验                        │
  │       calibration\                  <- 数据目录，已经建好（空的）         │
  │       tools\                        <- 分析工具，留给开发机用             │
  │                                                                          │
  │ ⚠️ 必须整个文件夹一起解压。不要在压缩包预览窗口里直接双击 exe。           │
  └──────────────────────────────────────────────────────────────────────────┘

  ┌─ 第 2 步 ────────────────────────────────────────────────────────────────┐
  │ 告诉**生产转码器**往哪里写事件。                                          │
  │                                                                          │
  │ ⚠️ 这一步是必须的！不设的话采集器永远收不到数据。                         │
  │                                                                          │
  │ 用"运行生产转码器的那个账号"设置下面两个系统环境变量。                    │
  │ 以管理员身份打开 PowerShell，执行：                                       │
  │                                                                          │
  │   [Environment]::SetEnvironmentVariable(                                 │
  │       "ONEXKT_CALIBRATION","1","Machine")                                │
  │   [Environment]::SetEnvironmentVariable(                                 │
  │       "ONEXKT_CALIBRATION_SPOOL","D:\1kt\collector\calibration","Machine")│
  │                                                                          │
  │ 注意 SPOOL 那个路径要和你解压的位置一致。                                 │
  │                                                                          │
  │ 设完要重启相关进程（或重启机器）才生效。                                  │
  │                                                                          │
  │ 图形界面替代做法：                                                        │
  │   此电脑 -^> 右键属性 -^> 高级系统设置 -^> 环境变量 -^> 系统变量 -^> 新建  │
  └──────────────────────────────────────────────────────────────────────────┘

  ┌─ 第 3 步 ────────────────────────────────────────────────────────────────┐
  │ 启动采集器。二选一：                                                      │
  │                                                                          │
  │ A. 先手动跑一次看看（推荐先这样做）                                       │
  │      双击  START-COLLECTOR.bat                                           │
  │      窗口会一直开着，这就是在工作。Ctrl+C 或关窗口 = 停止。               │
  │                                                                          │
  │ B. 让它开机自动跑（长期采集就用这个）                                     │
  │      双击  INSTALL-SCHEDULED-TASK.bat                                    │
  │      然后按它打印出来的提示，去任务计划程序里改三个设置（脚本改不了）。    │
  │      不想自动了：双击 UNINSTALL-SCHEDULED-TASK.bat                        │
  └──────────────────────────────────────────────────────────────────────────┘

  启动顺序无所谓：
    * 采集器可以先启动、后启动、随时重启
    * 生产转码器完全不等采集器，也不读采集器
    * 采集器没跑的时候，事件只是堆在 events\pending\ 里，等采集器起来再消费


================================================================================
  2. 怎么确认它在正常工作
================================================================================

  双击  CHECK-INSTALL.bat
  它会做三项只读检查，并把结果写进 check-report.txt。关键看：

    * "dataset": { "records": N }   N 在涨 = 正在记录，正常
    * "pending_events"              正常时应该接近 0
                                      一直几百上千 = 采集器没在跑，或者看错目录了
    * 最后一行 [OK] files=... errors=0

  再看数据有没有真的在长：

    dir D:\1kt\collector\calibration\samples

  出现 2026-XX-XX.jsonl 这样的文件，就是在正常采集。


================================================================================
  3. 日常命令（可选，都能省）
================================================================================

  在 D:\1kt\collector\ 目录下打开 cmd 或 PowerShell：

    # 看状态（只读）
    x265-calibration-collector.exe --headless --status --spool calibration

    # 体检数据集（只读，采集过程中随时能跑）
    x265-calibration-collector.exe --headless --validate calibration

    # 干跑一遍：只校验不写入（排查问题用）
    x265-calibration-collector.exe --headless --once --dry-run --watch calibration

    # 看日志
    type calibration\errors\collector.log

    # 看有没有坏事件
    dir calibration\events\failed
    type calibration\errors\rejected_events.jsonl

  退出码含义：
    0 = 正常        2 = 参数写错了
    3 = 已经有一个采集器在跑（锁文件保护，数据不会坏）
    4 = 内部错误    5 = 体检发现数据集有问题


================================================================================
  4. 出问题了怎么办
================================================================================

  ┌────────────────────────────────────┬─────────────────────────────────────┐
  │ 症状                                │ 原因 / 处理                          │
  ├────────────────────────────────────┼─────────────────────────────────────┤
  │ samples\ 一直是空的                 │ 生产那个账号没设 ONEXKT_CALIBRATION，│
  │                                     │ 或者 SPOOL 指到别的目录了            │
  ├────────────────────────────────────┼─────────────────────────────────────┤
  │ events\pending\ 一直涨但没记录       │ 采集器没在跑，或者 watch 的目录不对  │
  ├────────────────────────────────────┼─────────────────────────────────────┤
  │ events\failed\ 里有文件              │ 事件不符合 schema.json。同目录下有    │
  │                                     │ 个 .error.txt 写了原因，不用管也能跑 │
  ├────────────────────────────────────┼─────────────────────────────────────┤
  │ 退出码 3                            │ 已经有一个采集器在跑了，关掉多余的   │
  ├────────────────────────────────────┼─────────────────────────────────────┤
  │ 记录里 "complete": false            │ 生产那边没提供某个字段。             │
  │                                     │ completeness.missing 会列出来，      │
  │                                     │ 采集器**不会编造**值，这是正常的     │
  ├────────────────────────────────────┼─────────────────────────────────────┤
  │ 记录里 job_final_status 是空的       │ 那个任务的最终事件没到（生产被中途   │
  │                                     │ 杀了）。等 900 秒后也会落盘（带标记）│
  ├────────────────────────────────────┼─────────────────────────────────────┤
  │ 杀毒软件报毒 / 文件被删              │ 新编译的未签名单文件 exe 常被启发式  │
  │                                     │ 误报。把这个目录加白名单，不要关杀毒 │
  └────────────────────────────────────┴─────────────────────────────────────┘


================================================================================
  5. 一个月期间绝对不要做的事
================================================================================

  ✗ 不要改 x265.json
  ✗ 不要改 x265_scaling.json
  ✗ 不要升级 ffmpeg / 驱动 / 转码器版本
  ✗ 不要改 preset

  这个月的数据只有在"配置从头到尾固定不变"的前提下才有分析价值。
  中途改了任何一个，前后数据就不能放在一起拟合了。

  采集器自己不会碰这些东西，它只读不写。


================================================================================
  6. 一个月之后怎么做
================================================================================

  全部都在长期那台机器上做，不需要 Python、不需要开发机：

  ┌─ 第 1 步 ────────────────────────────────────────────────────────────────┐
  │ 收尾：把因为生产被中断而没等到 job 结束的记录也落盘（会带 incomplete 标记）│
  │                                                                          │
  │   x265-calibration-collector.exe --headless --drain-buffered ^            │
  │                                   --spool calibration                     │
  └──────────────────────────────────────────────────────────────────────────┘

  ┌─ 第 2 步 ────────────────────────────────────────────────────────────────┐
  │ 出分析报告。直接双击：                                                    │
  │                                                                          │
  │     ANALYZE-DATA.bat                                                     │
  │                                                                          │
  │ 报告会打印在窗口里，同时存成 analysis-report.txt。                        │
  │ 内容是：源分布（分辨率/FPS/编码/位深/色度/码率/时长/source class）、       │
  │ scaling 因子、各参数实际取值（merange / rc-lookahead / gop-lookahead /    │
  │ min-keyint / 动态 VBV）、成功率 / 失败率 / 重试率 / fallback 率 /         │
  │ 编码速度 / 压缩比 / 数据完整度。                                          │
  └──────────────────────────────────────────────────────────────────────────┘

  ┌─ 第 3 步 ────────────────────────────────────────────────────────────────┐
  │ 停掉采集器（任务计划程序里停掉任务，或关掉那个窗口）                       │
  └──────────────────────────────────────────────────────────────────────────┘

  ┌─ 第 4 步 ────────────────────────────────────────────────────────────────┐
  │ 把这些拷回开发机（要审计的话再带上 events\archive\ 和 errors\）：          │
  │                                                                          │
  │     calibration\samples\           <- 数据本体，最要紧的就是这个           │
  │     analysis-report.txt            <- 顺手把报告也带回去                  │
  └──────────────────────────────────────────────────────────────────────────┘

  想在机器上再看别的，tools\ 里还有两个：

    tools\x265-analyze.exe  <数据集目录>                 直接调分析器
    tools\x265-analyze.exe  <数据集目录> --json out.json 机器可读版
    tools\x265-deploy.exe   offline-check                静态确认不碰网络
    tools\x265-verify.exe   --exe <某个exe>              验证exe自包含
    tools\x265-verify.exe   --help

  拿到报告之后，参数优化是**另一个 session、回到 main 分支上做**。
  这个分支只负责采集，不负责调参。


================================================================================
  7. 这个包里各个文件是干什么的
================================================================================

  START-HERE.txt                     一段话指引（英文）
  QUICKSTART.zh-CN.txt               本文件
  README.txt                         完整英文文档（架构、事件生命周期、数据模型等）
  x265-calibration-collector.exe     采集器本体。自包含，不需要 Python
  START-COLLECTOR.bat                手动启动
  CHECK-INSTALL.bat                  只读自检 -> check-report.txt
  ANALYZE-DATA.bat                   出分析报告 -> analysis-report.txt
  VERIFY-PACKAGE.bat                 验证每个 exe 都自包含 -> verify-report.txt
  INSTALL-SCHEDULED-TASK.bat         注册开机自启
  UNINSTALL-SCHEDULED-TASK.bat       取消开机自启
  schema.json                        事件格式定义。exe 内已自带一份，这份是备用/查阅
  collector.toml                     可选配置模板（扫描间隔、等待超时、严格模式）
  VERSION                            版本号
  PACKAGE-CONTENTS.txt               包内每个文件的大小 + SHA-256 + 构建信息
  SHA256SUMS.txt                     只有校验和，方便比对
  calibration\                       数据目录（samples / events / summaries / errors / state）
  tools\x265-analyze.exe             离线分析器（独立 exe，不需要 Python）
  tools\x265-verify.exe              验证 exe 自包含（独立 exe，不需要 Python）
  tools\x265-deploy.exe              部署辅助：打印计划任务命令、离线检查
  tools\README.txt                   上面三个工具怎么用

  ★ 整个包不需要 Python。四个 exe 各自带着自己的运行时。
    目标机上没有 Python 是完全没有问题的，连分析也不用装。

  架构一句话：生产转码器和采集器是**两个平级的独立进程**，
  既不是谁启动谁，也没有 RPC / stdout 耦合，只通过
  calibration\events\pending\ 这个文件目录通信。

  详细边界、事件生命周期、数据字段清单，看 README.txt。
